# AI 助手假设实例存在 - 解决方案

> **问题**: 在新机器上使用时，AI 助手总是假设已有龙虾实例，导致体验不佳

**发现时间**: 2026-03-11  
**严重程度**: ⚠️ 中等（影响新用户体验）  
**状态**: ✅ 已解决

---

## 🐛 问题描述

### 现象

在**全新机器**上首次使用时：
```
用户: "帮我配置飞书"
AI: "好的，我为 openclaw-feishu-2774 配置飞书..."  ❌

问题: 
- 新机器上根本没有 openclaw-feishu-2774
- AI 自动假设这个实例存在
- 导致命令执行失败
```

### 影响

- ❌ 用户体验差（莫名其妙的实例名）
- ❌ 命令执行失败（实例不存在）
- ❌ 新用户困惑（以为系统有问题）

---

## 🔍 根本原因

### 原因分析

**问题根源**: 文档中到处都是**硬编码的示例实例名**

**问题文件**:
1. `AGENTS.md` - 技能包说明中使用 `openclaw-feishu-2774` 作为示例
2. `docs/01-使用指南/*.md` - 使用指南中的命令示例
3. `skills/*/SKILL.md` - 技能包文档中的示例命令

**AI 的误判逻辑**:
```
AI 读取 AGENTS.md → 看到 "openclaw-feishu-2774" 
→ 误以为这是用户的实例 
→ 直接使用该名称执行命令 
→ 失败（实例不存在）
```

---

## ✅ 解决方案

### 核心修复

**原则**: 所有文档中的实例名必须是**通用占位符**，不能是具体名称

#### 修复 1: AGENTS.md 添加警告

在 `AGENTS.md` 顶部添加：

```markdown
## ⚠️ 重要提示 - AI 助手必读

### 🚨 不要假设用户已有实例！

**正确做法**:
1. 🔍 **先检查实例是否存在**:
   python skills/openclaw-manager/scripts/instance_manager.py list

2. 📋 **如果列表为空**: 引导用户创建实例
3. 📋 **如果列表有实例**: 使用实际存在的实例名
```

#### 修复 2: 替换所有硬编码实例名

**替换前**:
```bash
# ❌ 硬编码具体实例名
python skills/openclaw-manager/scripts/instance_manager.py start openclaw-feishu-2774
```

**替换后**:
```bash
# ✅ 使用通用占位符
python skills/openclaw-manager/scripts/instance_manager.py start <实例名>
```

#### 修复 3: 更新工作流程

**新的工作流程**:
```
Step 0: 🔍 先执行 instance_manager.py list 检查现有实例
Step 1: 理解需求
Step 2: 确定技能包
Step 3: 执行操作
Step 4: 验证结果
```

#### 修复 4: 创建新机器部署指南

创建 `docs/01-使用指南/新机器首次使用.md`，提供清晰的新环境部署流程。
