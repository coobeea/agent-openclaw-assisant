# 经验总结：OpenClaw 配置文件严格的 Schema 校验

> 记录日期：2026-03-12
> 触发场景：在实现多智能体架构时，测试创建智能体并重启实例失败。

---

## 🐛 问题现象

在使用 `agent_manager.py` 创建新智能体后，重启 OpenClaw 实例失败，进程直接退出。

查看实例日志 (`workspace/logs/openclaw-feishu-2774.log`) 发现如下报错：

```log
Invalid config at /Users/lifeng/.../.openclaw/openclaw.json:
- agents: Unrecognized key: "agents"
│
◇  Config ───────────────────────────────────────────────────╮
│                                                            │
│  Config invalid; doctor will run with best-effort config.  │
│                                                            │
├────────────────────────────────────────────────────────────╯
│
◇  Unknown config keys ─╮
│                       │
│  - agents.agents      │
│                       │
├───────────────────────╯
```

---

## 🔍 问题原因分析

### 1. 我们的错误做法（兼容性陷阱）
在编写 `agent_manager.py` 时，我们发现旧的配置文件中智能体列表的键名可能是 `agents.agents`，而新版本源码中定义的是 `agents.list`。

为了"兼容"，我们写了这样的代码：
```python
# 试图同时保留两个键，或者在读取时做 fallback
agents = config.get('agents', {}).get('list', config.get('agents', {}).get('agents', []))
```
并在写入时，不小心把 `agents.agents` 这个旧键保留在了 `openclaw.json` 中。

### 2. OpenClaw 源码的严格校验
我们之前拉取了 OpenClaw 的源码，在 `src/config/schema.ts` 和 `src/config/zod-schema.ts` 中可以看到，OpenClaw 使用了 `zod` 进行了**极其严格的配置校验**。

它不仅校验必需字段，还启用了 `strict()` 模式（不允许出现未定义的未知键）。
一旦发现配置文件中存在未定义的键（如 `agents.agents`），OpenClaw 就会认为配置被破坏，拒绝启动并提示运行 `openclaw doctor --fix`。

---

## 💡 经验与教训

### 1. 永远不要在配置文件中留存"废弃/兼容"字段
- **教训**：在修改第三方系统的配置文件时，**不要自作聪明地保留旧字段以求"兼容"**。
- **正确做法**：必须严格遵循目标系统当前版本的 Schema 定义。如果发现旧字段，应该在读取后**主动清理掉**，然后只写入符合最新 Schema 的字段。

### 2. 重启实例后必须检查日志
- **教训**：通过命令行发送 `kill` 和 `node index.js` 后，进程可能在几百毫秒后因为配置错误而崩溃。仅仅看到 "PID 已启动" 是不够的。
- **正确做法**：在执行重启操作后，必须 `sleep 2`，然后 `tail` 查看日志，确认出现了类似 `[ws] client ready` 或 `event-dispatch is ready` 的成功标志。

### 3. OpenClaw 的配置哲学
- OpenClaw 的配置解析器（Config Parser）是防御性编程的典范。它宁可拒绝启动，也不使用可能引发歧义的配置。
- 在后续开发其他技能包（如模型配置、插件配置）时，写入 `openclaw.json` 的任何字段都必须先查阅源码中的 `zod-schema.*.ts`，确保字段名拼写和层级完全正确。

---

## ✅ 修复方案

我们在 `agent_manager.py` 中彻底移除了对 `agents.agents` 的写入，并添加了清理逻辑：

```python
# 读取时
agents_config = config.get('agents', {})
agents = agents_config.get('list', [])

# 如果存在旧的错误格式数据，合并过来
if 'agents' in agents_config and isinstance(agents_config['agents'], list):
    agents.extend(agents_config['agents'])
    # 彻底删除错误的键，防止 OpenClaw 启动报错
    del agents_config['agents']

# 写入时只写正确的键
agents_config['list'] = agents
```

通过这次修复，实例成功启动，并成功加载了多账号（`bot_002`）的长连接。
