> **频率**: 多次出现

## ❌ 问题现象

### 用户反馈
- 飞书机器人提示"需要配对"
- 用户发送消息后，机器人完全没反应
- 批准配对后，依然没有回复

### 日志表现
```
[feishu] feishu[default]: received message from ou_xxx
[feishu] feishu[default]: pairing request sender=ou_xxx
（之后没有任何处理日志）
```

**关键特征**:
- ✅ 消息被接收 (`received message`)
- ❌ 没有回复日志
- ⚠️  反复显示 `pairing request`

---

## 🔍 根本原因

### 原因 1: 配对未完成

**OpenClaw 的配对机制**:
1. 用户首次发送消息
2. 系统生成配对请求和配对码
3. 保存到 `credentials/feishu-pairing.json`
4. **需要手动批准配对**
5. 批准后添加到 `devices/paired.json`

**配对文件位置**:
```
workspace/lobsters/{instance-name}/
├── credentials/
│   └── feishu-pairing.json      # 待配对请求
└── devices/
    └── paired.json              # 已配对设备
```

### 原因 2: 批准配对后未重启

**关键发现**: ⚠️ **批准配对后必须重启实例才能生效！**

即使已经：
- ✅ 清空了 `feishu-pairing.json` 中的请求
- ✅ 添加到了 `paired.json`

**但如果没有重启，OpenClaw 仍然使用旧的配对信息！**

### 原因 3: 去重机制

如果多次发送相同或相似的消息，可能被去重（dedup）机制过滤。

**去重缓存位置**:
```
workspace/lobsters/{instance-name}/feishu/dedup/default.json
```

### 步骤 2: 批准配对

#### 方式 A: 通过 Web UI（推荐）

1. 打开 Web UI（从 `status` 命令获取完整 URL）
2. 找到"Pairing Requests"或"配对请求"
3. 找到对应的用户请求
4. 点击"Approve"批准

#### 方式 B: 通过脚本自动批准

```bash
cd workspace/lobsters/{instance-name}

cat > /tmp/approve_pairing.js << 'EOF'
const fs = require('fs');

// 读取配对请求
const credFile = './credentials/feishu-pairing.json';
const cred = JSON.parse(fs.readFileSync(credFile, 'utf8'));

if (cred.requests.length === 0) {
  console.log('❌ 没有待配对请求');
  process.exit(1);
}

const userId = cred.requests[0].id;
const userName = cred.requests[0].meta.name;
const code = cred.requests[0].code;

console.log(`📋 配对请求:`);
console.log(`   用户: ${userName}`);
console.log(`   配对码: ${code}`);
console.log(`   用户ID: ${userId}\n`);

// 清空配对请求
cred.requests = [];
fs.writeFileSync(credFile, JSON.stringify(cred, null, 2));
console.log('✅ 已清空配对请求\n');

// 添加到已配对设备
const pairedFile = './devices/paired.json';
const paired = JSON.parse(fs.readFileSync(pairedFile, 'utf8'));

const deviceId = `feishu:${userId}`;
paired[deviceId] = {
  deviceId: deviceId,
  platform: 'feishu',
  clientId: 'feishu-user',
  clientMode: 'feishu',
  role: 'user',
  roles: ['user'],
  scopes: ['user.chat', 'user.conversation'],
  approvedScopes: ['user.chat', 'user.conversation'],
  tokens: {},
  createdAtMs: Date.now(),
  approvedAtMs: Date.now(),
  meta: {
    name: userName,
    userId: userId,
    channel: 'feishu',
    approved: true
  }
};

fs.writeFileSync(pairedFile, JSON.stringify(paired, null, 2));
console.log('✅ 已添加到已配对设备');
console.log(`   设备ID: ${deviceId}`);
console.log(`   用户: ${userName}\n`);

console.log('⚠️  下一步: 必须重启实例才能生效！');
EOF

node /tmp/approve_pairing.js
```

### 步骤 3: ⚠️ **重启实例（必须！）**

## 🚨 关键要点

### ⚠️ 最重要的一点

> **批准配对后，必须重启实例才能生效！**

这是最容易被忽略的步骤，导致问题看起来"已经修复但还是不行"。

### 配对码会过期

每次重启后，如果用户重新发送消息，会生成**新的配对码**。

**示例**:
- 第1次配对码: `AHTJLMNJ`
- 重启后第2次: `CHVPDPUJ`

所以：
1. 查看最新的配对码
2. 批准后立即重启
3. 不要让用户等待太久

### 配对文件的作用

| 文件 | 作用 | 什么时候清空 |
|------|------|-------------|
| `credentials/feishu-pairing.json` | 存储待配对请求 | 批准后清空 `requests` 数组 |
| `devices/paired.json` | 存储已配对设备 | 添加新的设备ID |

### 2. 添加配对检查到健康检查

修改 `scripts/health_check.py`，添加配对状态检查：

```python
def check_pairing_status(self, instance_path: Path) -> Tuple[bool, str]:
    """检查配对状态"""
    pairing_file = instance_path / 'credentials' / 'feishu-pairing.json'
    
    if not pairing_file.exists():
        return True, "无配对请求"
    
    try:
        with open(pairing_file, 'r') as f:
            pairing = json.load(f)
        
        pending_count = len(pairing.get('requests', []))
        
        if pending_count > 0:
            return False, f"有 {pending_count} 个待配对请求"
        else:
            return True, "无待配对请求"
    except Exception as e:
        return False, f"检查失败: {e}"
```

## 💡 经验总结

### 核心要点

> **配对 = 批准 + 重启**

不是只批准就完了，**必须重启实例**！

### 常见错误

❌ **错误**: 批准配对后直接测试  
✅ **正确**: 批准配对 → **重启实例** → 再测试

❌ **错误**: 使用旧的配对码  
✅ **正确**: 总是查看最新的 `feishu-pairing.json`

❌ **错误**: 忘记清空去重缓存  
✅ **正确**: 多次尝试后清空 `dedup/default.json`

### 记住这个流程

```
用户发消息 
  ↓
生成配对请求
  ↓
批准配对（脚本或Web UI）
  ↓
⚠️ 重启实例（必须！）
  ↓
用户再次发消息
  ↓
✅ 正常回复
```
