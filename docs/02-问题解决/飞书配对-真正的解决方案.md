## ✅ 正确的配对机制

### OpenClaw的真实逻辑

通过阅读源码 `src/pairing/pairing-store.ts` 发现：

**OpenClaw判断用户是否已配对，依赖的是**:
```
credentials/feishu-default-allowFrom.json
```

**不是** `devices/paired.json`！

### 文件作用

| 文件 | 作用 | 是否必需 |
|------|------|---------|
| `credentials/feishu-pairing.json` | 存储待配对请求 | ✅ 必需 |
| `credentials/feishu-default-allowFrom.json` | **存储已批准的用户ID列表** | ✅ **必需** |
| `devices/paired.json` | ❌ OpenClaw不使用 | ❌ 删除 |

## 🔧 正确的解决步骤

### 步骤 1: 查看配对请求

```bash
cat workspace/lobsters/{name}/credentials/feishu-pairing.json
```

记录：
- 用户ID（如 `ou_ffb9c807b0ef0a11b0a4d13a5fb93a3a`）
- 配对码（如 `9BMQKX24`）
- 用户名

---

### 步骤 2: 创建 allowFrom 文件

**这是关键步骤！**

```bash
cat > workspace/lobsters/{name}/credentials/feishu-default-allowFrom.json << 'EOF'
{
  "version": 1,
  "allowFrom": [
    "ou_ffb9c807b0ef0a11b0a4d13a5fb93a3a"
  ]
}
EOF
```

**文件格式**:
- `version`: 必须是 `1`
- `allowFrom`: 数组，包含已批准的用户OpenID

**支持多用户**:
```json
{
  "version": 1,
  "allowFrom": [
    "ou_user1",
    "ou_user2",
    "ou_user3"
  ]
}
```

---

### 步骤 3: 清空配对请求

```bash
cat > workspace/lobsters/{name}/credentials/feishu-pairing.json << 'EOF'
{
  "version": 1,
  "requests": []
}
EOF
```

---

### 步骤 4: 删除错误文件（如果存在）


---

### 步骤 5: 重启实例


## 🚨 为什么之前一直失败？

### 问题分析

```
❌ 我们操作的文件: devices/paired.json
✅ OpenClaw实际读取: credentials/feishu-default-allowFrom.json

结果: OpenClaw找不到 allowFrom 文件，认为用户没配对
     → 每次收到消息都发起配对请求
     → 陷入死循环
```

### 源码证据

`src/pairing/pairing-store.ts` 第542-562行：

```typescript
export async function readChannelAllowFromStore(
  channel: PairingChannel,
  env: NodeJS.ProcessEnv = process.env,
  accountId?: string,
): Promise<string[]> {
  const resolvedAccountId = resolveAllowFromAccountId(accountId);
  
  // 读取 feishu-default-allowFrom.json
  const scopedPath = resolveAllowFromPath(channel, env, resolvedAccountId);
  const scopedEntries = await readAllowFromStateForPath(channel, scopedPath);
  
  // 向后兼容：也读取 feishu-allowFrom.json
  const legacyPath = resolveAllowFromPath(channel, env);
  const legacyEntries = await readAllowFromStateForPath(channel, legacyPath);
  
  return dedupePreserveOrder([...scopedEntries, ...legacyEntries]);
}
```

**关键**:
- 读取 `{channel}-{accountId}-allowFrom.json`（默认账号是 `feishu-default-allowFrom.json`）
- **不读取** `paired.json`

## 💡 核心要点

### 一句话总结

> **配对 = 创建 allowFrom 文件 + 重启！**

### 记住这3点
