# 方案 C：云端生产环境

> 在真实的云 K8s 服务上部署，验证生产级性能和可靠性

---

## 📋 方案概述

### 目标
- 在真实云环境验证架构
- 测试大规模并发和性能
- 验证生产级特性（高可用、弹性伸缩、监控告警）
- 为正式上线做准备

### 与本地方案的区别

| 对比项 | 本地 K8s | 云端 K8s |
|--------|---------|---------|
| **节点** | Docker 容器模拟 | 真实的物理/虚拟机 ✅ |
| **网络** | 本地网络 | 公网/VPC ✅ |
| **存储** | 本地磁盘 | 云盘/对象存储 ✅ |
| **负载均衡** | 模拟 | 真实 LB ✅ |
| **高可用** | 无法测试 | 多可用区 ✅ |
| **性能** | 受限于本地机器 | 可按需扩容 ✅ |
| **成本** | 免费 | 按使用付费 💰 |
| **稳定性** | 开发环境 | 生产级 ✅ |

```bash
cat > production-deployment.yaml <<'EOF'

        - name: REDIS_PASSWORD
          valueFrom:
            secretKeyRef:
              name: redis-secret

        - name: OSS_ENDPOINT
```

## 🌐 第四步：配置负载均衡和域名

### 1. 创建 Ingress（阿里云 SLB）

```bash
cat > ingress.yaml <<'EOF'
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: openclaw-ingress
  namespace: openclaw
  annotations:
    # 阿里云 SLB 配置
    kubernetes.io/ingress.class: "nginx"
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
    nginx.ingress.kubernetes.io/force-ssl-redirect: "true"
    # 限流
    nginx.ingress.kubernetes.io/limit-rps: "100"
spec:
  rules:
  - host: api.yourdomain.com  # 替换为你的域名
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: openclaw-scheduler
            port:
              number: 8080
  tls:
  - hosts:
    - api.yourdomain.com
    secretName: openclaw-tls  # SSL 证书
EOF

kubectl apply -f ingress.yaml
```

### 2. 配置 SSL 证书

```bash
# 方式 1：使用 cert-manager 自动申请 Let's Encrypt 证书
kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.13.0/cert-manager.yaml

# 创建 ClusterIssuer
cat > letsencrypt-prod.yaml <<'EOF'
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt-prod
spec:
  acme:
    server: https://acme-v02.api.letsencrypt.org/directory
    email: your-email@example.com
    privateKeySecretRef:
      name: letsencrypt-prod
    solvers:
    - http01:
        ingress:
          class: nginx
EOF

kubectl apply -f letsencrypt-prod.yaml

# 方式 2：手动上传证书
kubectl create secret tls openclaw-tls \
  --cert=path/to/tls.crt \
  --key=path/to/tls.key \
  -n openclaw
```

### 3. 配置域名解析

```
在域名提供商（如阿里云域名、GoDaddy）：

记录类型: A
主机记录: api
记录值: <Load Balancer IP>  # 从 kubectl get svc 获取

或使用 CNAME:
记录类型: CNAME
主机记录: api
记录值: <Load Balancer 域名>
```

## 🧪 第六步：压力测试

### 使用 K6 压测

```bash
# 安装 K6
brew install k6

# 创建测试脚本
cat > load-test.js <<'EOF'
import http from 'k6/http';
import { check, sleep } from 'k6';

export let options = {
  stages: [
    { duration: '2m', target: 100 },  // 2分钟内到100用户
    { duration: '5m', target: 100 },  // 保持100用户5分钟
    { duration: '2m', target: 200 },  // 增加到200用户
    { duration: '5m', target: 200 },  // 保持200用户5分钟
    { duration: '2m', target: 0 },    // 降到0
  ],
};

export default function () {
  let agent_id = `agent-${Math.floor(Math.random() * 1000)}`;
  
  let res = http.post('https://api.yourdomain.com/allocate', 
    JSON.stringify({ agent_id: agent_id }),
    { headers: { 'Content-Type': 'application/json' } }
  );
  
  check(res, {
    'status is 200': (r) => r.status === 200,
    'response time < 500ms': (r) => r.timings.duration < 500,
  });
  
  sleep(1);
}
EOF

# 运行测试
k6 run load-test.js
```
