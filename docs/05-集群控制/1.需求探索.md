# 多用户智能体平台（OpenClaw 类 SaaS）核心架构设计文档
## 一、文档概述
本文档基于 OpenClaw 原生机制与 Buda 类云端智能体平台的实际落地逻辑，梳理**多用户领用独立智能体**的核心架构、资源调度、数据持久化、性能优化方案，解决海量用户场景下的服务器负载、数据隔离、响应延时等关键问题，为平台开发提供可落地的设计依据。

## 二、核心认知：智能体的本质
1. **原生 OpenClaw 模式**
    - 1 个智能体（Agent）= 1 个独立常驻容器/进程
    - 容器绑定智能体，数据存储在容器内部
    - 适合个人本地使用，**不适合海量用户 SaaS 平台**
2. **商用平台（Buda）模式**
    - 智能体 = 逻辑数据（灵魂）+ 临时执行环境（身体）
    - 智能体配置、记忆、文件等数据独立持久化
    - 执行容器按需创建、复用、销毁，不与智能体绑定

## 三、关键问题与结论
### 问题1：一个用户能否创建多个智能体？
**结论**：可以。
- 一个用户可创建 N 个智能体，每个智能体拥有独立 ID、配置、记忆、文件空间
- 每个智能体仅为**数据库记录 + 独立存储目录**，不占用运行资源

### 问题2：海量用户+多智能体，每个都分配常驻容器，服务器是否会崩溃？
**结论**：会，该模式完全不可商用。
- 单个容器至少占用 100MB~300MB 内存
- 10000 用户将带来 TB 级内存占用，成本与性能均无法支撑

### 问题3：临时容器是否每回答一个问题就重建+销毁？
**结论**：不会，否则延时极高、体验极差。
- 采用**会话级复用 + 空闲超时回收**机制
- 会话期间复用同一容器，停止对话 3~15 分钟后销毁
- 高阶方案使用**热池（Hot Pool）** 进一步优化延时

### 问题4：临时容器销毁后，智能体配置、聊天记录、文件如何保存？
**结论**：所有数据与容器解耦，统一存储在外部持久化服务中。
- 容器仅负责执行，不存储任何状态数据
- 数据永久留存，更换容器不影响智能体记忆与状态

## 四、完整架构设计
### 1. 整体流程
用户请求 → API 网关（鉴权+路由）→ 调度服务 → 容器热池 → 执行任务 → 数据回写持久化服务 → 容器回收/复用

### 2. 数据持久化方案（灵魂存储）
| 数据类型 | 存储介质 | 说明 |
|----------|----------|------|
| 智能体基础配置（人格/角色/技能） | MySQL/PostgreSQL/MongoDB | 单条数据库记录，无运行时资源占用 |
| 聊天记录/对话历史 | MongoDB/PostgreSQL | 按智能体 ID 关联，会话时加载 |
| 长期记忆/知识库 | 向量数据库（Milvus/Chroma） | 对话时检索注入，执行后更新 |
| 文件/工作区数据 | 对象存储（OSS/S3）/分布式文件系统 | 按智能体 ID 划分目录，执行时挂载 |
| 临时会话状态 | Redis | 超时自动清理，提升响应速度 |

### 3. 容器调度方案（身体管理）
#### （1）核心策略：热池（Hot Pool）
- 提前预热一批干净的基础 OpenClaw 容器，长期后台运行
- 容器无用户绑定、无用户数据，仅作为通用执行环境
- 支持自动扩缩容，高峰期扩容、低峰期缩容

#### （2）请求执行流程
1. 用户发送请求，携带智能体 ID
2. 调度服务从热池获取空闲容器
3. 挂载该智能体对应的持久化存储目录
4. 容器加载配置、记忆、文件并执行任务
5. 执行完成后，新数据回写持久化服务
6. 会话空闲超时后，卸载存储、清理容器并放回热池

#### （3）容器生命周期
- 运行中：会话期间持续复用
- 空闲回收：3~15 分钟无操作则回收至热池
- 销毁：容器污染/资源低峰时销毁，由热池自动补全

### 4. 网关与路由设计
- 统一域名入口，所有请求通过 API 网关转发
- 按智能体 ID 动态路由，**无需静态配置智能体列表**
- 网关负责鉴权、限流、日志审计，保障多租户数据隔离

## 五、架构优势
1. **成本极低**
    - 智能体为数据实体，不占用 CPU/内存
    - 少量容器即可支撑海量用户，资源利用率极高
2. **性能优秀**
    - 热池容器秒级响应，用户无明显延时
    - 会话复用容器，避免重复启动开销
3. **安全隔离**
    - 智能体数据独立存储，容器执行后彻底清理
    - 多租户无数据串扰，符合 SaaS 安全规范
4. **无限扩容**
    - 支持万级、十万级用户，无架构瓶颈
    - 存储与计算分离，可独立水平扩容

## 六、最终核心总结
1. 智能体 = 持久化数据（灵魂）+ 临时容器（身体）
2. 海量用户场景**禁止**为每个智能体创建常驻容器
3. 商用平台必须采用**容器热池 + 按需挂载 + 空闲回收**架构
4. 数据与执行环境彻底解耦，是实现长期记忆、低成本运营的核心
5. 网关动态路由替代静态配置，支撑无限多智能体接入
