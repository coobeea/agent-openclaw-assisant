## 📊 提取的关键经验

### 经验 #1: 模型 Provider 必须用官方名称

**来源**: agent-openclaws 历史问题，已修复 2-3 轮仍反复出现

**问题**:
- ❌ 使用自造名称 `dashscope-subscription`
- ❌ API 类型用 `openai-compatible`（OpenClaw 不支持）
- ❌ models 字段是对象而不是数组

**正确**:
- ✅ 使用官方名称 `bailian`
- ✅ API 类型用 `openai-completions`
- ✅ models 字段必须是数组

**根本原因**: 不遵循官方规范，自己起名字

**教训**: 必须查看官方配置示例，严格使用官方名称

### 经验 #2: Web UI 访问必须用 `#token=`

**来源**: agent-openclaws 历史问题，几乎每个用户都遇到

**问题**:
- ❌ 用 `?token=`（Query Parameter）
- 症状: 刷新后显示 "device identity required"

**正确**:
- ✅ 用 `#token=`（Hash Fragment）
- 原因: Hash 不会发送到服务器，刷新时保留

**教训**: 在工具输出和文档中明确标注格式

### 经验 #3: 配置文件格式要严格

**来源**: agent-openclaws 历史问题

**常见错误**:
- ❌ 模型名称用 `|` → ✅ 用 `/`
- ❌ 缺少 provider 前缀 → ✅ 必须有
- ❌ 布尔值是字符串 → ✅ 改为布尔值
- ❌ 数字是字符串 → ✅ 改为数字
- ❌ 数组是对象 → ✅ 改为数组

**教训**: 使用配置验证工具，提供完整的配置示例

### 经验 #4: 从源头预防问题

**方法**:
1. ✅ 在配置模板中固化正确配置
2. ✅ 在创建工具中验证配置
3. ✅ 在诊断工具中自动检测问题
4. ✅ 在文档中明确强调规范

**效果**: 避免问题反复出现
