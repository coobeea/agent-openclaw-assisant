## 🔍 根本原因分析

### 1. API Rate Limit

**问题**: 百炼 API 调用频率限制

**可能原因**:
- 短时间内多次重试
- API Key 配额不足
- 同一个 API Key 被多个实例使用

**检查方法**:
```bash
# 查看 API Key 配置
cat workspace/data/models.json
```

---

### 2. Model Serving Error

**问题**: "There are no suitable clusters"

**可能原因**:
- 百炼服务端问题（服务器集群故障）
- 模型配置错误
- API Key 权限不足

**这是百炼服务端的问题，不是我们的问题**

---

### 3. LLM Request Timeout

**问题**: 请求超过10分钟未响应

**可能原因**:
- 模型服务不可用
- 网络问题
- 请求过于复杂

---

## ✅ 建议方案

### 方案 1: 检查 API Key 配额

```bash
# 查看当前配置
cat workspace/data/models.json

# 确认：
# 1. API Key 是否有效
# 2. 是否有调用配额
# 3. 是否被多个实例使用
```

---

### 方案 2: 配置重试策略

在 `openclaw.json` 中配置重试参数：
```json
{
  "models": {
    "defaults": {
      "retryOnError": true,
      "maxRetries": 3,
      "retryDelay": 5000
    }
  }
}
```

---

### 方案 3: 添加备用模型

配置多个模型，当主模型失败时自动切换：
```json
{
  "agents": {
    "defaults": {
      "models": {
        "bailian/qwen3.5-plus": {},
        "bailian/qwen-turbo": {},  // 备用
        "bailian/qwen-max": {}     // 备用
      }
    }
  }
}
```

---

### 方案 4: 监控和告警

创建监控脚本，检测错误率：

  | grep "isError=true" \

## 💡 临时解决方法

### 如果频繁遇到 Rate Limit

1. **增加重试间隔**
   ```json
   "retryDelay": 10000  // 从5秒增加到10秒
   ```

2. **减少并发请求**
   ```json
   "maxConcurrentRequests": 1  // 串行处理
   ```

3. **升级 API Key**
   - 联系百炼升级配额

---

### 如果遇到 Model Serving Error

1. **检查服务状态**
   - 访问百炼控制台
   - 查看服务是否正常

2. **切换模型**
   ```bash
   # 使用其他模型
   bailian/qwen-turbo  # 更快，可能更稳定
   ```

3. **等待服务恢复**
   - 这是百炼服务端问题
   - 通常会自动恢复
