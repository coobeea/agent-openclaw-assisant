## 📊 多平台架构

### 架构图

```
源文件（单一数据源）
    skills/
    ├── openclaw-manager/
    │   └── SKILL.md
    ├── openclaw-deploy/
    │   └── SKILL.md
    └── ...
        ↓
    （软链接）
        ↓
    ┌───────────────┬────────────────┬────────────────┐
    ↓               ↓                ↓
.cursor/skills/ .claude/skills/  .coder/skills/
    ↓               ↓                ↓
Cursor IDE    Claude Desktop      Coder
```

---

### 核心原则

1. **单一数据源**: 所有技能包源文件在 `skills/` 目录
2. **软链接共享**: 通过软链接让多个平台共享相同的技能包
3. **平台识别**: 每个 AI IDE 自动识别各自的技能包目录
4. **统一管理**: 修改源文件后，所有平台立即生效

## 🔧 技能包管理统一流程

### 添加新技能包（所有平台同步）

1. **在源目录创建技能包**：
   ```bash
   mkdir -p skills/new-skill-name
   # 创建 SKILL.md 和其他文件
   ```

2. **为所有平台创建软链接**：
   ```bash
   # Cursor
   cd .cursor/skills
   ln -s ../../skills/new-skill-name new-skill-name
   
   # Claude Desktop
   cd .claude/skills
   ln -s ../../skills/new-skill-name new-skill-name
   
   # Coder
   cd .coder/skills
   ln -s ../../skills/new-skill-name new-skill-name
   ```

3. **完成** - 所有平台立即可用新技能包

## 🎓 设计经验

### 核心理念：单一数据源

**为什么使用软链接而不是复制？**

| 方案 | 优点 | 缺点 |
|------|------|------|
| **复制** | 简单 | ❌ 每个平台都有副本<br>❌ 修改需要同步多处<br>❌ 容易不一致 |
| **软链接** ✅ | ✅ 单一数据源<br>✅ 修改立即生效<br>✅ 永远保持一致 | 需要理解软链接 |

---

### 多平台架构优势

1. **开发效率**：
   - 修改一次，所有平台生效
   - 无需手动同步
   - 减少维护成本

2. **用户选择**：
   - 用户可以选择喜欢的 AI IDE
   - 体验完全一致
   - 降低平台绑定

3. **项目灵活性**：
   - 易于支持新平台（只需创建新的软链接目录）
   - 技能包独立于平台
   - 便于迁移和共享
