## 📋 任务背景

### 问题描述

用户反馈：**"我们需要定义 py 的版本"**

**核心问题**:
1. ❌ 项目缺少明确的 Python 版本要求定义
2. ❌ 没有标准的版本锁定文件（如 `.python-version`）
3. ❌ requirements.txt 缺少版本说明注释
4. ❌ 没有 pyproject.toml（Python 项目标准配置）
5. ❌ env-checker 要求 3.12+，但项目未明确定义最低版本

---

## 🎯 解决方案

### 版本策略

制定分层的 Python 版本策略：

| 层级 | 版本 | 定义文件 | 说明 |
|------|------|---------|------|
| **目标版本** | 3.12.8 | `.python-version` | pyenv 锁定，开发标准 |
| **推荐版本** | 3.12+ | env-checker | 自动安装版本 |
| **最低版本** | 3.10+ | pyproject.toml | 兼容性门槛 |
| **测试版本** | 3.12.8, 3.14.2 | requirements.txt | 经过验证的版本 |

---

### 设计原则

1. **兼容性优先**: 最低 Python 3.10，覆盖更多系统
2. **性能优先**: 推荐 Python 3.12+，性能提升约 15-40%
3. **统一优先**: 使用 `.python-version` 和 env-checker 确保团队一致
4. **自动化优先**: env-checker 自动处理 Python 安装和版本问题

### 版本策略对比

| 方案 | 最低版本 | env-checker | pyproject.toml | .python-version | 优点 | 缺点 |
|------|---------|------------|----------------|-----------------|------|------|
| **当前方案** ✅ | 3.10+ | 3.12+ | >=3.10 | 3.12.8 | 兼容性+性能 | 版本略不统一 |
| 方案B | 3.12+ | 3.12+ | >=3.12 | 3.12.8 | 版本完全统一 | 不支持旧系统 |
| 方案C | 3.10+ | 3.10+ | >=3.10 | 3.10.x | 完全统一 | 性能较差 |

**选择: 当前方案**

**理由**:
1. **兼容性优先**: Python 3.10+ 覆盖大多数现代系统
2. **自动升级**: env-checker 自动安装 3.12.8（最佳版本）
3. **灵活性**: 允许用户使用现有 3.10/3.11
4. **性能**: 推荐版本 3.12+ 性能优秀
5. **用户友好**: 不强制升级，但引导最佳实践

## 🚨 常见问题

### Q1: 为什么 pyproject.toml 要求 >=3.10，而 env-checker 要求 >=3.12？

**答**: 这是有意的设计，为了兼容性和性能的平衡。

- `pyproject.toml` (**最低门槛**): 允许用户使用现有 3.10/3.11
- `env-checker` (**推荐标准**): 自动安装最佳版本 3.12.8

**好处**:
- ✅ 用户有 3.10/3.11 → 可以用
- ✅ 用户没Python → 自动安装 3.12.8
- ✅ 两全其美

---

### Q2: 我的系统是 Python 3.14，会有问题吗？

**不会！** Python 3.14 >= 3.12，完全兼容。

env-checker 会检测到：
```
[INFO] 找到 Python: python3 (版本 3.14.2)
[INFO] 版本状态: 兼容 (高于目标)  ✅
```

---

### Q3: 如何确保团队使用统一的 Python 版本？

**推荐方式**: 使用 env-checker

```bash
# 所有成员运行
bash skills/env-checker/scripts/setup.sh

# env-checker 会自动:
# - 检测系统 Python
# - 如果版本 < 3.12，自动安装 3.12.8
# - 创建统一的虚拟环境

# 结果: 所有成员都使用 Python 3.12+
```

---

### Q4: 能否强制所有用户使用 Python 3.12？

**可以，但不推荐**。

如果必须强制，需要修改 `pyproject.toml`:
```toml
requires-python = ">=3.12"
```

**后果**:
- ⚠️ 用户有 3.10/3.11 将无法使用
- ⚠️ 降低兼容性
- ⚠️ 增加部署难度

---

### Q5: pyproject.toml 的 dependencies 和 requirements.txt 的关系？

**关系**: 保持一致，但用途不同

- `requirements.txt`: pip 直接安装用（`pip install -r requirements.txt`）
- `pyproject.toml`: Python 项目标准配置（`pip install -e .`）

**建议**: 
- 开发时使用 `requirements.txt`（env-checker 使用）
- 发布时使用 `pyproject.toml`（pip/PyPI 标准）
