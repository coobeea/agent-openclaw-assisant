# 多智能体多渠道架构探讨

> 目标：探讨在同一个 OpenClaw 实例中，如何支持多个智能体分别对接到不同的渠道平台。

---

## 🎯 核心问题

当前 OpenClaw 的架构是：
- 一个实例（Instance）
- 一个或多个智能体（Agent）
- 多个渠道（Channel，如飞书、QQ、企微等）

**我们需要探讨的问题是**：
1. 同一个实例中，能否创建多个智能体？（✅ 已经可以）
2. **每个智能体能否单独绑定到不同的渠道？**（例如：Agent A 接飞书，Agent B 接 QQ）
3. **如果同一个平台（如飞书）有多个机器人账号，如何区分绑定？**

---

## 🔍 源码级架构分析

通过拉取 OpenClaw 源码（版本: `v1.0` 左右），我们深入分析了它的配置和路由机制。

### 1. 渠道的多账号支持 (`accounts`)

在 `src/config/types.channels.ts` 中，我们发现 OpenClaw 原生支持**单渠道多账号**。

以 Slack（或扩展渠道）为例：
```typescript
export type ExtensionChannelConfig = {
  enabled?: boolean;
  defaultAccount?: string;
  accounts?: Record<string, unknown>; // ✨ 支持多个账号配置
  // ...
};
```

这意味着，在 `openclaw.json` 中，我们可以这样配置两个飞书机器人：
```json
"channels": {
  "feishu": {
    "enabled": true,
    "accounts": {
      "bot_kefu": {
        "appId": "cli_kefu_123",
        "appSecret": "..."
      },
      "bot_hr": {
        "appId": "cli_hr_456",
        "appSecret": "..."
      }
    }
  }
}
```

### 2. 路由绑定的多账号区分 (`accountId`)

在 `src/config/types.agents.ts` 中，路由绑定规则 `AgentBindingMatch` 完美支持了 `accountId`：

```typescript
export type AgentBindingMatch = {
  channel: string;          // 渠道名称，例如 "feishu"
  accountId?: string;       // ✨ 账号ID，用于区分同一个渠道下的不同机器人！
  peer?: { kind: ChatType; id: string }; 
  // ...
};
```

## 🏗️ 最终架构方案

**结论：OpenClaw 源码不仅支持多渠道路由，还完美支持"同渠道多账号"的精确路由！**

### 完整配置示例

假设我们有：
- **飞书客服机器人** (账号ID: `bot_kefu`) -> 交给 `agent-service` 处理
- **飞书HR机器人** (账号ID: `bot_hr`) -> 交给 `agent-hr` 处理
- **QQ机器人** -> 交给 `agent-qq` 处理

**对应的 `openclaw.json` 应该是这样的**：

```json
{
  "channels": {
    "feishu": {
      "enabled": true,
      "accounts": {
        "bot_kefu": { "appId": "cli_kefu_123", "appSecret": "..." },
        "bot_hr": { "appId": "cli_hr_456", "appSecret": "..." }
      }
    },
    "qq": {
      "enabled": true,
      "appId": "qq_789",
      "appSecret": "..."
    }
  },
  "agents": {
    "list": [
      { "id": "agent-service", "name": "客服智能体" },
      { "id": "agent-hr", "name": "HR智能体" },
      { "id": "agent-qq", "name": "QQ智能体" }
    ]
  },
  "bindings": [
    {
      "comment": "飞书客服机器人 -> 客服智能体",
      "agentId": "agent-service",
      "match": { 
        "channel": "feishu", 
        "accountId": "bot_kefu"  // 👈 精确匹配飞书的 bot_kefu 账号
      }
    },
    {
      "comment": "飞书HR机器人 -> HR智能体",
      "agentId": "agent-hr",
      "match": { 
        "channel": "feishu", 
        "accountId": "bot_hr"    // 👈 精确匹配飞书的 bot_hr 账号
      }
    },
    {
      "comment": "QQ渠道 -> QQ智能体",
      "agentId": "agent-qq",
      "match": { 
        "channel": "qq"          // 👈 匹配整个 QQ 渠道（因为QQ只有一个账号）
      }
    }
  ]
}
```

## 📋 技能包改造计划

为了支持这个强大的特性，我们需要改造以下技能包：

### 1. `openclaw-agent` 技能包
- **新增功能**：支持创建新的智能体（在 `agents/` 目录下创建新文件夹，并更新 `openclaw.json` 的 `agents.list`）。

### 2. `openclaw-channel` 技能包
- **支持多账号**：配置渠道时，询问用户是"覆盖默认配置"还是"添加新账号"。
  - 如果是添加新账号，要求提供一个 `accountId`（如 `bot_kefu`）。
  - 将配置写入 `channels.<平台>.accounts.<accountId>`。
- **支持路由绑定**：配置完成后，询问："这个账号的消息由哪个智能体处理？（默认: main）"。
  - 自动在 `bindings` 数组中追加一条包含 `channel` 和 `accountId` 的路由规则。
