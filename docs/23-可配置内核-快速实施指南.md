# 可配置内核 - 快速实施指南

> **5 分钟理解**：如何让系统支持 OpenClaw 和 QwenPaw 两种内核？

---

## 1. 核心思路（3个关键点）

### ① 统一接口（Interface）

```go
// 定义统一的内核接口
type KernelInterface interface {
    StreamChat(req *ChatRequest) (<-chan ChatEvent, error)
    CreateAgent(agentID, workspace string) error
    HealthCheck() error
}
```

**作用**：无论是 OpenClaw（WebSocket）还是 QwenPaw（HTTP），Scheduler 都通过这个接口调用。

### ② 适配器模式（Adapter）

```
OpenClawAdapter  ─┐
                  ├─> 都实现 KernelInterface
QwenPawAdapter   ─┘
```

**作用**：每个适配器负责处理各自的协议细节，Scheduler 不关心。

### ③ 工厂模式（Factory）

```go
func CreateKernel(kernelType string) KernelInterface {
    if kernelType == "openclaw" {
        return NewOpenClawAdapter()
    } else if kernelType == "qwenpaw" {
        return NewQwenPawAdapter()
    }
}
```

**作用**：根据配置动态创建对应的内核。

## 3. 核心代码（极简版）

### Step 1: 定义接口

```go
// internal/kernel/interface.go

package kernel

type ChatRequest struct {
    AgentID    string `json:"agent_id"`
    SessionKey string `json:"session_key"`
    Message    string `json:"message"`
}

type ChatEvent struct {
    Type    string `json:"type"`    // "delta" | "done" | "error"
    Content string `json:"content"` // 增量内容
    Error   string `json:"error,omitempty"`
}

type KernelInterface interface {
    StreamChat(req *ChatRequest) (<-chan ChatEvent, error)
}
```

### Step 2: OpenClaw 适配器

```go
// internal/kernel/adapters/openclaw.go

package adapters

import (
    "github.com/gorilla/websocket"
    "openclaw-scheduler/internal/kernel"
)

type OpenClawAdapter struct {
    conn *websocket.Conn
}

func NewOpenClawAdapter(endpoint, token string) *OpenClawAdapter {
    // 建立 WebSocket 连接
    conn, _ := websocket.Dial(fmt.Sprintf("ws://%s/gateway", endpoint), ...)
    // 执行 connect.challenge 握手
    // ...
    return &OpenClawAdapter{conn: conn}
}

func (a *OpenClawAdapter) StreamChat(req *kernel.ChatRequest) (<-chan kernel.ChatEvent, error) {
    ch := make(chan kernel.ChatEvent, 10)
    
    // 发送 chat.send RPC
    a.conn.WriteJSON(map[string]interface{}{
        "type": "req",
        "method": "chat.send",
        "params": map[string]interface{}{
            "message": req.Message,
            "sessionKey": req.SessionKey,
        },
    })
    
    // 监听 WebSocket 事件
    go func() {
        for {
            var frame map[string]interface{}
            a.conn.ReadJSON(&frame)
            
            if frame["event"] == "chat" && frame["payload"]["state"] == "delta" {
                ch <- kernel.ChatEvent{
                    Type: "delta",
                    Content: extractContent(frame),
                }
            }
        }
    }()
    
    return ch, nil
}
```

### Step 3: QwenPaw 适配器

```go
// internal/kernel/adapters/qwenpaw.go

package adapters

import (
    "bufio"
    "net/http"
    "openclaw-scheduler/internal/kernel"
)

type QwenPawAdapter struct {
    client *http.Client
}

func NewQwenPawAdapter(endpoint string) *QwenPawAdapter {
    return &QwenPawAdapter{client: &http.Client{}}
}

func (a *QwenPawAdapter) StreamChat(req *kernel.ChatRequest) (<-chan kernel.ChatEvent, error) {
    ch := make(chan kernel.ChatEvent, 10)
    
    // 发送 HTTP POST 请求
    payload := map[string]interface{}{
        "sender_id": req.AgentID,
        "content_parts": []map[string]string{
            {"type": "text", "text": req.Message},
        },
    }
    resp, _ := http.Post(fmt.Sprintf("http://%s/api/console/chat", endpoint), "application/json", ...)
    
    // 解析 SSE 流
    go func() {
        scanner := bufio.NewScanner(resp.Body)
        for scanner.Scan() {
            line := scanner.Text()
            if strings.HasPrefix(line, "data: ") {
                data := strings.TrimPrefix(line, "data: ")
                var event map[string]interface{}
                json.Unmarshal([]byte(data), &event)
                
                if content, ok := event["content"].(string); ok {
                    ch <- kernel.ChatEvent{
                        Type: "delta",
                        Content: content,
                    }
                }
            }
        }
    }()
    
    return ch, nil
}
```

### Step 4: 工厂模式

```go
// internal/kernel/factory.go

package kernel

func CreateKernel(kernelType, endpoint, token string) (KernelInterface, error) {
    switch kernelType {
    case "openclaw":
        return adapters.NewOpenClawAdapter(endpoint, token), nil
    case "qwenpaw":
        return adapters.NewQwenPawAdapter(endpoint), nil
    default:
        return nil, fmt.Errorf("未知内核: %s", kernelType)
    }
}
```

### Step 5: Scheduler 改造

```go
// internal/api/api.go

func ChatStream(c *gin.Context) {
    // 1. 获取配置
    kernelType := os.Getenv("KERNEL_TYPE") // "openclaw" | "qwenpaw"
    
    // 2. 分配容器
    container, _ := k8s.AllocateContainerByKernel(kernelType)
    
    // 3. 创建内核适配器
    kernel, _ := kernel.CreateKernel(
        kernelType,
        container.PodIP,
        "token",
    )
    
    // 4. 发送聊天请求
    eventChan, _ := kernel.StreamChat(&kernel.ChatRequest{
        AgentID: req.AgentID,
        Message: req.Content,
    })
    
    // 5. 转换为 SSE 格式（前端）
    c.Header("Content-Type", "text/event-stream")
    for event := range eventChan {
        fmt.Fprintf(c.Writer, "data: %s\n\n", event.Content)
        c.Writer.(http.Flusher).Flush()
    }
}
```

## 4. 配置切换

### 方式 1：环境变量（全局）

```bash
# 使用 OpenClaw
export KERNEL_TYPE=openclaw

# 使用 QwenPaw
export KERNEL_TYPE=qwenpaw
```

### 方式 2：HTTP Header（动态）

```javascript
// 前端指定内核
fetch('/api/chat/stream', {
  headers: {
    'X-Kernel-Type': 'openclaw'  // 或 'qwenpaw'
  }
})
```

### 方式 3：K8s ConfigMap

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: scheduler-config
data:
  KERNEL_TYPE: "openclaw"  # 修改这里即可切换
```

## 5. 部署架构

### 单内核部署（推荐入门）

```
Frontend (Vue3)
    ↓ HTTP/SSE
Scheduler (Go)
    ↓ WebSocket/HTTP
OpenClaw Pods (x3)
```

### 混合部署（高级）

```
Frontend (Vue3)
    ↓ HTTP/SSE
Scheduler (Go) ─────┬───────────┐
                    ↓           ↓
            OpenClaw Pods    QwenPaw Pods
               (x2)             (x2)
```

**容器分配逻辑：**
```go
func AllocateContainerByKernel(kernelType string) {
    if kernelType == "openclaw" {
        return AllocateContainer("openclaw")
    } else {
        return AllocateContainer("qwenpaw")
    }
}
```

## 9. 常见问题

### Q1: 两种内核功能会完全一致吗？

**A**: 不一定。两者的核心功能（聊天、流式输出）是统一的，但一些高级特性可能有差异。我们通过接口抽象来保证核心功能的一致性。

### Q2: 性能有差异吗？

**A**: 是的。OpenClaw 使用 WebSocket（全双工），理论上延迟更低；QwenPaw 使用 HTTP + SSE（单向流），兼容性更好。建议根据场景选择。

### Q3: 可以同时运行两种内核吗？

**A**: 可以。通过 K8s 部署两组 Pods，Scheduler 根据请求动态选择。

### Q4: 切换内核需要重启吗？

**A**: 
- **全局切换**（环境变量）：需要重启 Scheduler
- **动态切换**（HTTP Header）：无需重启

### Q5: 如果 OpenClaw 升级了怎么办？

**A**: 只需更新 `OpenClawAdapter`，不影响 QwenPaw。这就是抽象层的优势。

## 11. 总结

**核心价值**：
- 让系统具备**选择能力**，而不是被单一内核绑定
- 通过**适配器模式**隐藏协议差异
- 为未来**扩展更多内核**奠定基础

**关键决策**：
- ✅ 现在实施：适合有 Python AI/ML 需求的团队
- ⏸️ 暂缓实施：适合对 OpenClaw 满意的团队

**记住**：架构的价值在于**灵活性**，而不是复杂性。如果当前 OpenClaw 能满足所有需求，可以先不实施。
