### 3. 创建 Agent 流程（已修复）
```bash
1. 前端发送请求 → POST /api/agents/create
   {
     "user_id": 4,
     "name": "测试助手",
     "kernel_type": "qwenpaw",
     "model_config": { ... }  # 可选
   }

2. Scheduler 执行:
   a. 生成 agent_id
   b. 创建 workspace 目录: /data/agents/{agent_id}/
   c. 写入 config.json:
      {
        "kernel_type": "qwenpaw",
        "agent_info": { "name": "...", "description": "..." },
        "model": {
          "provider": "ollama",
          "model_name": "gemma4:e4b",
          "base_url": "http://host.docker.internal:11434",
          "temperature": 0.7,
          "max_tokens": 2000
        }
      }
   d. 保存元数据到数据库（包含 workspace_path）
   e. 预热分配容器

3. 结果:
   ✅ Host 上: /Users/lifeng/.../workspace/agent-xxx/config.json
   ✅ Scheduler Pod: /data/agents/agent-xxx/config.json
   ✅ QwenPaw Pod: /data/agents/agent-xxx/config.json
```

### 4. 聊天流程（已修复）
```bash
1. 前端发送消息 → POST /api/chat/stream/v2
   {
     "agent_id": "agent-4-xxx",
     "message": "你好"
   }
   Header: X-Kernel-Type: qwenpaw

2. Scheduler 执行:
   a. 从数据库查询 agent 的 workspace_path
   b. 分配容器（kernel-aware）
   c. 创建 kernel adapter
   d. 从 workspace/config.json 读取模型配置
   e. 将配置传递给 kernel（QwenPaw/OpenClaw）

3. Kernel Adapter:
   - QwenPawAdapter: 读取 config.json → 传递给 QwenPaw API
   - OpenClawAdapter: 读取 config.json → 传递给 OpenClaw Gateway
```

## ⚠️  已知问题：QwenPaw 模型配置

**问题描述**:
- Scheduler 正确读取了 workspace 的 config.json
- 配置已传递给 QwenPaw API（`model_config` 字段）
- 但 QwenPaw 返回空内容（0 字符）

**可能原因**:
1. **QwenPaw API 不支持动态模型配置**
   - QwenPaw 可能使用内部的 `/app/working/config.json`
   - 请求中的 `model_config` 可能被忽略

2. **QwenPaw 内部 Ollama 配置问题**
   - QwenPaw 需要在自己的 config.json 中配置 LLM
   - 或者需要通过 QwenPaw UI 进行配置
