## 数据流详解

### 创建实例流程

```
用户: "创建实例 openclaw-prod-01"
  ↓
Cursor AI 识别 openclaw-manager 技能包
  ↓
读取 SKILL.md，理解如何创建实例
  ↓
调用 scripts/instance_manager.py create openclaw-prod-01
  ↓
instance_manager.py:
  1. 读取 global.yaml 获取 workspace_root
  2. 调用 utils.ensure_workspace_exists(instance_id)
  3. 只创建顶层目录: workspace/openclaw-prod-01/
  4. 执行: openclaw init --workspace workspace/openclaw-prod-01/
  ↓
OpenClaw CLI 初始化实例
  ↓
OpenClaw 自己创建内部结构（config/, data/, logs/, plugins/）
  ↓
返回成功消息给用户
```

### 添加渠道流程

```
用户: "添加飞书渠道"
  ↓
Cursor AI 识别 openclaw-channel 技能包
  ↓
调用 scripts/channel_manager.py add
  ↓
channel_manager.py:
  1. 验证实例存在
  2. 使用 CredentialEncryptor 加密 app_secret
  3. 执行: openclaw channel add --workspace ... --platform feishu --app-id ... --app-secret ...
  ↓
OpenClaw CLI 配置渠道
  ↓
返回成功消息
```

### 部署到 Docker 流程

```
用户: "部署到 Docker"
  ↓
Cursor AI 识别 openclaw-deploy 技能包
  ↓
调用 scripts/deploy_docker.sh
  ↓
deploy_docker.sh:
  1. 复制 templates/Dockerfile
  2. 复制 templates/docker-compose.yml
  3. 替换环境变量（INSTANCE_ID, WORKSPACE_PATH）
  4. 执行: docker-compose up -d
  ↓
Docker 构建镜像并启动容器
  ↓
返回容器ID和状态
```

## 安全架构

### 凭证加密流程

```
明文凭证（API Key, App Secret）
  ↓
[CredentialEncryptor.encrypt()]
  ↓
Fernet 加密（对称加密）
  ↓
Base64 编码
  ↓
存储到 OpenClaw 配置
  ↓
密钥存储在: workspace/{instance}/.keyfile (权限 600)
```

### 安全层级

```
Level 1: Git 排除
  ├── workspace/  (完全不提交)
  ├── *.key, *.env  (凭证文件)
  └── logs/  (日志文件)

Level 2: 文件权限
  ├── .keyfile (600 - 仅所有者可读写)
  └── workspace/ (700 - 仅所有者可访问)

Level 3: 凭证加密
  ├── Fernet 对称加密
  ├── 显示时自动遮罩 (sk-...xyz)
  └── 传输时使用加密后的值

Level 4: 访问控制
  └── 通过 OpenClaw CLI 操作（不直接修改配置）
```

## 软链接机制

### 设计目的

解决 Cursor 技能包的识别和开发体验问题。

### 工作原理

```
开发流程:
  编辑源文件
      ↓
  skills/openclaw-manager/SKILL.md
      ↓
  保存 (Cmd+S)
      ↓
  立即生效！Cursor 通过软链接读取最新内容
      ↓
  .cursor/skills/openclaw-manager/SKILL.md (软链接)
      ↓
  Cursor AI 使用新版本
```

### 对比其他方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| **软链接** ✅ | 实时生效、单一数据源、便于版本控制 | 需要理解软链接 |
| 复制文件 | 简单直接 | 需要同步、容易出错 |
| 直接在 .cursor/ 开发 | Cursor 直接识别 | 不符合多技能包仓库设计 |

## 工作空间设计

### 保真原则 ⭐

**核心思想**: 不假设 OpenClaw 的内部结构

```
❌ 错误设计:
workspace/
└── openclaw-prod-01/
    ├── config/     ← 我们创建的（错误！）
    ├── data/       ← 我们创建的（错误！）
    └── logs/       ← 我们创建的（错误！）

✅ 正确设计:
workspace/
└── openclaw-prod-01/   ← 我们只创建这一层
    └── (OpenClaw 自己管理内部结构)
```

### 实现方式

```python
def ensure_workspace_exists(self, instance_id: str) -> Path:
    """
    只创建实例的顶层目录，不预定义内部结构
    """
    instance_path = self.get_instance_path(instance_id)
    instance_path.mkdir(parents=True, exist_ok=True)  # 只创建顶层
    return instance_path
    # ❌ 不要: (instance_path / "config").mkdir()
    # ❌ 不要: (instance_path / "data").mkdir()
```

### 路径配置化

```yaml
# shared/configs/global.yaml
workspace_root: ./workspace  # 可以是:
  # 相对路径: ./workspace, ../data
  # 绝对路径: /var/lib/openclaw
  # 用户目录: ~/openclaw-workspace
```

```python
# 获取配置化的路径
utils = OpenClawUtils()
instance_path = utils.get_instance_path("openclaw-prod-01")
# 返回: Path(workspace_root) / "openclaw-prod-01"
```

## 设计决策记录

### ADR-001: 使用软链接激活技能包

**背景**: 需要让 Cursor 识别技能包，同时保持源文件的统一管理。

**决策**: 使用软链接将 `skills/` 链接到 `.cursor/skills/`

**理由**:
- Cursor 自动识别 `.cursor/skills/`
- 源文件在 `skills/` 便于版本控制
- 实时生效，无需同步

**权衡**: 需要理解软链接概念

### ADR-002: 工作空间保真设计

**背景**: 如何管理 OpenClaw 的工作空间目录？

**决策**: 只创建顶层目录，不预定义内部结构

**理由**:
- OpenClaw 可能更新内部结构
- 避免假设导致兼容性问题
- 尊重 OpenClaw 的自主管理

**权衡**: 需要信任 OpenClaw CLI

### ADR-003: 通过 CLI 而非直接操作配置

**背景**: 如何与 OpenClaw 交互？

**决策**: 优先使用 OpenClaw CLI，而非直接修改配置文件

**理由**:
- CLI 更稳定（官方接口）
- 适应版本更新
- 避免配置格式错误

**权衡**: 依赖 CLI 的存在和稳定性

### ADR-004: Fernet 凭证加密

**背景**: 如何保护敏感凭证？

**决策**: 使用 Fernet 对称加密

**理由**:
- 安全高效
- Python cryptography 库内置
- 易于实现和维护

**权衡**: 密钥管理的责任
