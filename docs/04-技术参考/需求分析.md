# OpenClaw 管理技能包 - 需求分析文档

## 1. 项目概述

### 1.1 项目背景
OpenClaw 是一个开源的个人AI助手平台，支持多种消息渠道（飞书、QQ、企业微信、钉钉等）。为了更好地管理和部署 OpenClaw 实例（"龙虾军团"），需要开发一个统一的管理技能包。

### 1.2 项目目标
- 提供 OpenClaw 实例的全生命周期管理能力
- 支持多种部署模式（主机模式、容器模式）
- 实现多渠道插件的统一管理
- 提供智能体和模型的配置管理
- 统一管理工作空间和运行数据

## 2. 核心功能需求

**功能描述**
- 从 GitHub (openclaw/openclaw) 拉取源码

**实现要点**
- 检测是否有官方打包版本可用

## 2.9 关键设计原则

### 工作空间管理原则 ⚠️ 重要

**原则 1：路径可配置，不硬编码**
- 工作空间路径通过 `global.yaml` 配置
- 支持相对路径、绝对路径、用户目录
- 代码中通过配置获取路径，不写死

```python
# ✅ 正确：从配置读取
workspace_root = config['global']['workspace_root']

# ❌ 错误：硬编码路径
workspace_root = "./workspace"  # 不要这样做！
```

**原则 2：结构不预定义，由 OpenClaw 管理**
- 我们只创建实例的顶层目录（如 `workspace/openclaw-prod-01/`）
- 实例内部的目录结构完全由 OpenClaw 创建和管理
- 不同版本的 OpenClaw 可能有不同的内部结构
- 我们的代码不对内部结构做任何假设

```bash
# ✅ 正确：只创建顶层目录
mkdir -p "$workspace_root/$instance_id"
openclaw init --workspace "$workspace_root/$instance_id"

# ❌ 错误：预创建内部目录
mkdir -p "$workspace_root/$instance_id/config"
mkdir -p "$workspace_root/$instance_id/data"
mkdir -p "$workspace_root/$instance_id/logs"
```

**原则 3：通过命令行工具操作，不直接操作文件**
- 优先使用 OpenClaw 的命令行工具
- 避免直接读写实例内部的文件
- 保持与 OpenClaw 版本更新的兼容性

```bash
# ✅ 正确：使用 OpenClaw 命令
openclaw config --workspace "$instance_path" get key

# ❌ 错误：直接读取配置文件
# cat "$instance_path/config/openclaw.yaml"
```

### 8.3 技能包划分说明

#### 核心技能包
**`openclaw-manager`** - OpenClaw 统一管理技能包
- 作用范围：实例的创建、启动、停止、删除
- 核心功能：实例生命周期管理、工作空间管理
- 触发时机：创建/管理OpenClaw实例、查看实例状态

#### 扩展技能包
各功能模块独立成技能包，可根据需要单独使用：

1. **`openclaw-deploy`** - 部署管理
   - 主机模式部署（Systemd服务）
   - 容器模式部署（Docker/K8s）
   
2. **`openclaw-plugin`** - 插件管理
   - 插件安装/卸载/更新
   - 四大平台插件集成
   
3. **`openclaw-channel`** - 渠道管理
   - 渠道配置增删改查
   - 凭证安全管理
   
4. **`openclaw-model`** - 模型管理

### 8.5 工作空间管理

所有 OpenClaw 实例的工作空间统一存放在 `workspace/` 目录：

```
workspace/
├── openclaw-{instance-id}/          # 实例工作空间
│   └── ...                          # 内部结构由 OpenClaw 自行管理
│                                    # 我们不预定义其目录结构
```

**重要说明：**
- ⚠️ `workspace/` 目录只是一个**存储位置**
- ⚠️ 每个实例内部的目录结构**由 OpenClaw 自己创建和管理**
- ⚠️ 我们的技能包**不预定义**实例内部的目录结构
- ⚠️ 工作空间路径**可配置**，通过 `global.yaml` 的 `workspace_root` 设置
- ✅ 我们只负责创建顶层实例目录，指向给 OpenClaw
- ✅ OpenClaw 会根据其版本和配置自动创建所需的子目录

**路径配置示例：**
```yaml
# shared/configs/global.yaml
global:
  workspace_root: "./workspace"           # 相对路径（相对于项目根目录）
  # 或
  workspace_root: "/data/openclaw"        # 绝对路径
  # 或
  workspace_root: "~/openclaw-data"       # 用户主目录
```

**工作空间管理原则：**

1. **路径可配置** ✅
   - 通过 `global.yaml` 的 `workspace_root` 配置
   - 支持相对路径、绝对路径、用户目录
   - 不在代码中硬编码路径

2. **结构不预定义** ✅
   - 我们只创建实例的顶层目录（如 `workspace/openclaw-prod-01/`）
   - 实例内部的目录结构完全由 OpenClaw 管理
   - 不同版本的 OpenClaw 可能有不同的内部结构

3. **保持灵活性** ✅
   - 适应 OpenClaw 的版本升级
   - 适应不同的配置方式
   - 不对 OpenClaw 的实现做假设

4. **统一管理** ✅
   - 所有实例在同一个根目录下
   - 方便备份和迁移
   - 便于资源监控和管理

### 8.6 Cursor 技能包规范

#### SKILL.md 文件要求
每个技能包必须包含一个 `SKILL.md` 文件，格式如下：

```markdown
---
name: skill-name                    # 必需，最大64字符，小写字母/数字/连字符
description: >-                     # 必需，最大1024字符，描述功能和触发时机
  Brief description of what this skill does. Use when...
---

# Skill Title

## Instructions
具体的使用说明...
```

#### 技能包结构规范
```
skill-name/
├── SKILL.md              # 必需 - 主文件（建议<500行）
├── reference/            # 可选 - 详细参考文档
│   ├── topic1.md
│   └── topic2.md
└── scripts/              # 可选 - 工具脚本
    ├── script1.py
    ├── script2.sh
    └── requirements.txt  # Python依赖
```

#### 技能包编写原则
1. **简洁为王**: SKILL.md主文件建议在500行以内
2. **渐进式披露**: 详细内容放在 reference/ 目录
3. **一层引用**: 从SKILL.md直接引用reference文件
4. **第三人称描述**: description使用第三人称
5. **明确触发时机**: description包含"Use when..."说明

## 11. 风险与挑战

### 11.1 技术风险
- **OpenClaw API变化**: OpenClaw 持续更新，API可能变化
  - 应对：优先使用官方命令行工具，减少直接依赖内部API
- **多平台适配复杂**: 不同消息平台的认证和配置各不相同
  - 应对：提供统一的配置抽象层，插件化管理
- **技能包依赖管理**: 多个技能包之间的依赖关系
  - 应对：明确技能包边界，核心技能包独立可用

### 11.2 运维风险
- **实例资源冲突**: 多实例可能端口冲突或资源竞争
  - 应对：实现端口自动分配机制，资源隔离
- **数据安全**: 敏感信息泄露风险
  - 应对：加密存储，严格的 .gitignore 规则
- **工作空间管理**: 多实例工作空间可能占用大量磁盘空间
  - 应对：提供清理和归档机制

### 11.3 维护风险
- **版本兼容性**: OpenClaw 版本升级可能导致不兼容
  - 应对：版本锁定 + 渐进式升级策略
- **技能包更新**: 多个技能包独立更新可能导致不兼容
  - 应对：明确技能包版本依赖，提供兼容性测试

## 15. 技能包使用场景

## 16. 技能包协作机制

### 16.1 技能包独立性
- 每个技能包可以**独立使用**
- 核心技能包（openclaw-manager）无外部依赖
- 其他技能包依赖核心技能包

### 16.2 技能包组合使用
```
场景1: 快速启动（最小化）
  openclaw-manager

场景2: 生产部署（推荐）
  openclaw-manager + openclaw-deploy + openclaw-plugin + openclaw-channel

场景3: 完整管理（全功能）
  所有6个技能包
```

### 16.3 技能包调用链
```
用户请求
    ↓
Cursor AI (识别意图)
    ↓
选择合适的技能包
    ↓
执行技能包中的指令
    ↓
调用scripts/中的工具
    ↓
操作 OpenClaw 和工作空间
    ↓
返回结果给用户
```

### 16.4 数据共享机制
- **工作空间**: 所有技能包共享 `workspace/` 目录
- **配置文件**: 实例配置在各自工作空间中
- **全局配置**: 放在 `shared/configs/` 目录
- **工具脚本**: 可以跨技能包复用

### 19.3 快速参考命令（规划）

```bash
# 安装 OpenClaw
openclaw-manager install

# 创建实例
openclaw-manager create openclaw-prod-01

# 部署到主机
openclaw-deploy host openclaw-prod-01

# 安装飞书插件
openclaw-plugin install feishu --instance openclaw-prod-01

# 配置飞书渠道
openclaw-channel add feishu \
  --instance openclaw-prod-01 \
  --app-id xxx \
  --app-secret yyy

# 添加 AI 模型
openclaw-model add gpt4 \
  --provider openai \
  --api-key zzz

# 创建智能体
openclaw-agent create customer-service \
  --instance openclaw-prod-01 \
  --model gpt4 \
  --channel feishu

# 启动实例
openclaw-manager start openclaw-prod-01

# 查看状态
openclaw-manager status openclaw-prod-01

# 查看日志
openclaw-manager logs openclaw-prod-01 -f
```
