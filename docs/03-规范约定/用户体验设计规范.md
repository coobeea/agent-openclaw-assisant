## 1. 核心原则

### 1.1 用户说人话，AI 做技术活

**原则**: 用户不需要学习技术术语，用日常语言即可。

**✅ 好的示例**:
```
用户: "搞个飞书机器人"
AI: （自动执行7个技术步骤）
```

**❌ 不好的示例**:
```
用户: "搞个飞书机器人"
AI: "请运行 openclaw setup --workspace /path/to/..."
```

**实施要点**:
- 隐藏所有技术细节（命令、路径、配置文件等）
- 用用户能理解的语言反馈结果
- 技术问题转化为用户友好的描述

---

### 1.2 宽泛问题 → 精准引导

**原则**: 用户的问题可能很宽泛，AI 要主动引导到具体操作。

**✅ 好的示例**:
```
用户: "配置一下"
AI: "好的！请问你想配置什么？
     1. 配置消息平台（飞书、QQ、企微、钉钉）
     2. 配置 AI 模型（GPT-4、Claude等）
     3. 配置实例设置（端口、日志等）
     
     💬 选择数字或说具体内容"
```

**❌ 不好的示例**:
```
用户: "配置一下"
AI: "我不理解，请说清楚"
```

**实施要点**:
- 识别宽泛意图（如"配置"）
- 提供具体选项（2-4个）
- 引导用户做选择
- 降低用户的认知负担

---

### 1.3 主动提示下一步

**原则**: 每个操作完成后，主动告诉用户"接下来可以做什么"。

**✅ 好的示例**:
```
✅ 实例创建成功！

📋 实例信息:
   名称: openclaw-service-01
   状态: 运行中 🟢

🎯 接下来你可以:
   1. "配置飞书渠道" - 让机器人接入飞书
   2. "发送测试消息" - 测试功能
   3. "查看日志" - 检查运行情况
   
💬 直接告诉我你想做什么！
```

**❌ 不好的示例**:
```
✅ 实例创建成功！
（没有后续提示，用户不知道下一步该做什么）
```

**实施要点**:
- 完成操作后，列出2-4个可能的下一步
- 提供具体的命令示例
- 用 emoji 增强可读性
- 降低门槛（"直接告诉我"）

---

### 1.4 智能推荐，减少选择

**原则**: 能自动决策的就不问用户，必须问时提供推荐。

**✅ 好的示例**:
```
AI: "客服场景推荐 GPT-3.5（快速+经济）
     技术场景推荐 GPT-4（准确+强大）
     
     你的机器人用来做客服，我推荐 GPT-3.5。
     要改用 GPT-4 吗？（默认：GPT-3.5）"
```

**❌ 不好的示例**:
```
AI: "请选择模型：
     GPT-3.5、GPT-4、Claude-3、Gemini、LLaMA、..."
（用户：😵 太多选择了！）
```

**实施要点**:
- 根据场景自动推荐
- 说明推荐理由
- 提供简单的确认方式
- 设置合理的默认值

---

### 1.5 容错优先

**原则**: 用户说错、说得不专业，AI 也能理解。

**✅ 好的示例**:

| 用户说（不专业） | AI 理解为 | 处理方式 |
|----------------|---------|---------|
| "搞个机器人" | CREATE_INSTANCE | ✅ 创建实例流程 |
| "用飞书" | FEISHU_INTEGRATION | ✅ 飞书集成流程 |
| "配置" | AMBIGUOUS | ✅ 询问：配置什么？ |
| "不会用" | HELP | ✅ 提供教程 |

**❌ 不好的示例**:
```
用户: "搞个机器人"
AI: "未知命令，请使用标准语法"
```

**实施要点**:
- 宽泛的关键词匹配
- 同义词识别
- 模糊匹配
- 当无法确定时，列出可能的选项

## 2. 意图识别设计

### 2.1 意图分类体系

**5大意图分类**:

#### 1️⃣ 创建类 (CREATE)

**关键词**: 创建、新建、搭建、启动、部署、上线、搞、弄

**宽泛表达**:
- "搞个机器人"
- "弄个飞书的"
- "我想要一个..."

**识别规则**:
```python
def is_create_intent(user_input):
    keywords = ['创建', '新建', '搭建', '启动', '部署', '上线', '搞', '弄', '建', '做']
    return any(k in user_input for k in keywords)
```

**处理流程**:
1. 识别为创建意图
2. 询问基本信息（名称、用途）
3. 询问平台（如果用户没说）
4. 自动决策（模型、部署方式）
5. 执行创建流程
6. 反馈结果 + 提示下一步

---

#### 2️⃣ 查看类 (VIEW)

**关键词**: 查看、列表、状态、有哪些、运行、健康

**宽泛表达**:
- "有啥机器人"
- "看一下状态"
- "运行情况"

**识别规则**:
```python
def is_view_intent(user_input):
    keywords = ['查看', '列表', '状态', '有哪些', '有啥', '运行', '健康', '看']
    return any(k in user_input for k in keywords)
```

**处理流程**:
1. 识别为查看意图
2. 读取实例数据
3. 格式化显示（表格）
4. 高亮异常状态
5. 提示可用操作

---

#### 3️⃣ 配置类 (CONFIG)

**关键词**: 配置、设置、修改、更新、绑定

**宽泛表达**:
- "配置一下"
- "设置"
- "改一下配置"

**识别规则**:
```python
def is_config_intent(user_input):
    keywords = ['配置', '设置', '修改', '更新', '绑定', '改']
    specific = ['飞书', 'QQ', '模型', 'GPT', 'Claude', '渠道', '智能体']
    
    if any(k in user_input for k in keywords):
        # 如果有具体内容，直接执行
        if any(s in user_input for s in specific):
            return ('CONFIG_SPECIFIC', extract_target(user_input))
        # 否则询问
        else:
            return ('CONFIG_AMBIGUOUS', None)
```

**处理流程（具体）**:
1. 识别具体配置目标（如"飞书"）
2. 直接进入配置流程
3. 要求必需信息
4. 验证配置
5. 反馈结果

**处理流程（宽泛）**:
1. 识别为配置意图（但不具体）
2. 列出常见配置选项（2-4个）
3. 等待用户选择
4. 进入对应流程

---

#### 4️⃣ 运维类 (OPERATION)

**关键词**: 启动、停止、重启、删除、清理

**宽泛表达**:
- "启动一下"
- "关掉"
- "重新来"

**识别规则**:
```python
def is_operation_intent(user_input):
    keywords = {
        'start': ['启动', '开始', '运行', '跑'],
        'stop': ['停止', '关闭', '关掉', '停'],
        'restart': ['重启', '重新启动', '重来'],
        'delete': ['删除', '移除', '清除', '删']
    }
    
    for action, words in keywords.items():
        if any(w in user_input for w in words):
            return (action, extract_target(user_input))
```

**处理流程**:
1. 识别操作类型和目标
2. 删除类操作需要确认
3. 执行操作
4. 验证结果
5. 反馈状态

---

#### 5️⃣ 求助类 (HELP)

**关键词**: 怎么、如何、帮助、不会、教我、不懂

**宽泛表达**:
- "怎么用"
- "不太会"
- "教我一下"

**识别规则**:
```python
def is_help_intent(user_input):
    keywords = ['怎么', '如何', '帮助', '不会', '教我', '不懂', '不知道']
    return any(k in user_input for k in keywords)
```

**处理流程**:
1. 识别为求助意图
2. 提供快速入门指南
3. 推荐最常用操作（3个）
4. 提供示例命令
5. 互动式引导

---

### 2.2 意图识别优先级

当多个意图关键词同时出现时：

**优先级顺序**:
1. **具体操作** > 宽泛意图
2. **求助** > 其他（用户明确不会）
3. **创建** > 配置（新建优先）
4. **运维** > 查看（操作优先）

**示例**:
```
用户: "创建一个飞书机器人，不太会操作"
包含: CREATE + HELP

处理: 识别为 HELP（优先级更高）
→ 先提供创建教程，再引导创建
```

---

### 2.3 意图模糊处理

当无法确定意图时：

**处理方式**:
```
AI: "我可以帮你：
     1. 创建新的机器人实例
     2. 查看现有机器人状态
     3. 配置机器人功能
     
     请告诉我你想做什么？（说数字或描述都可以）"
```

**原则**:
- 不要说"我不理解"
- 提供具体选项（2-4个）
- 降低门槛（多种输入方式）

## 3. 对话流程设计

### 3.1 分步引导原则

**❌ 不要一次问太多**:
```
AI: "请提供以下信息：
     1. 实例名称
     2. 端口号
     3. AI模型
     4. 消息平台
     5. App ID
     6. App Secret
     7. 部署方式
     8. 日志级别"
     
用户: 😵 太复杂了！
```

**✅ 分步进行**:
```
AI: "首先，给这个机器人起个名字？
     （比如：客服小助手、技术顾问等）
     
     💡 提示：名字用来识别不同的机器人"
     
用户: "客服小助手"

AI: "很好！这个机器人主要用来做什么？
     1. 客服咨询
     2. 技术支持
     3. 通知推送
     4. 其他"
     
（逐步进行...）
```

**规则**:
- 每次只问1-2个问题
- 问题要具体明确
- 提供示例或提示
- 用 emoji 增强可读性

---

### 3.2 信息收集优先级

**必需信息优先**:
```
优先级 1（必需）:
  - 实例名称
  - 用途/场景
  - 平台选择

优先级 2（重要）:
  - App ID/Secret（如需对接平台）
  - API Key（如需AI功能）

优先级 3（自动决策）:
  - 端口号（自动分配）
  - 模型选择（自动推荐）
  - 部署方式（自动判断）
  - 日志级别（自动设置）
```

**流程**:
1. 只问必需的
2. 重要的等用户确认后再问
3. 能自动决策的都不问

---

### 3.3 对话模板

#### 模板 1: 引导式询问

```markdown
【问题】+ 【示例】+ 【提示】

示例:
"给这个机器人起个名字？
 （比如：客服小助手、技术顾问等）
 
 💡 提示：名字用来识别不同的机器人"
```

#### 模板 2: 选项式询问

```markdown
【问题】+ 【选项（2-4个）】+ 【其他】

示例:
"这个机器人主要用来做什么？
 1. 客服咨询
 2. 技术支持
 3. 通知推送
 4. 其他（请描述）"
```

#### 模板 3: 确认式询问

```markdown
【推荐】+ 【理由】+ 【确认】

示例:
"客服场景推荐 GPT-3.5（快速+经济）
 
 要使用 GPT-3.5 吗？（说"是"、"换其他"或"不确定"）"
```

#### 模板 4: 信息提供

```markdown
【说明】+ 【获取方式】+ 【格式提示】

示例:
"为了对接飞书，需要 App ID。
 
 🔗 获取方式:
 1. 访问 https://open.feishu.cn/app
 2. 创建应用（如果还没有）
 3. 复制 App ID
 
 💡 格式: cli_xxxxxxxx
 
 请提供 App ID:"
```

---

### 3.4 对话节奏控制

**快速通道**（用户很清楚）:
```
用户: "创建一个飞书客服机器人，名字叫客服001，

```

## 4. 智能决策设计

### 4.1 自动决策规则

#### 决策 1: AI 模型选择

**规则**:
```python
def auto_select_model(scenario):
    if scenario in ['客服', '咨询', '问答']:
        return 'gpt-3.5-turbo'  # 快速+经济
    elif scenario in ['技术', '编程', '分析']:
        return 'gpt-4'  # 准确+强大
    elif scenario in ['通知', '推送']:
        return None  # 无需AI
    else:
        return 'gpt-3.5-turbo'  # 默认
```

**说明**:
- 客服场景：GPT-3.5（响应快，成本低）
- 技术场景：GPT-4（理解深，准确度高）
- 通知场景：无需AI
- 未知场景：保守选择 GPT-3.5

---

#### 决策 2: 部署方式

**规则**:
```python
def auto_select_deploy_mode(environment):
    if '生产' in environment or 'prod' in environment.lower():
        return 'docker'  # 生产用容器
    elif '测试' in environment or 'test' in environment.lower():
        return 'process'  # 测试用进程
    elif environment == '':
        return 'process'  # 默认进程
    else:
        return 'process'  # 保守选择
```

**说明**:
- 明确说"生产"：用 Docker
- 明确说"测试"：用本地进程
- 未说明：用本地进程（更简单）

---

#### 决策 3: 端口分配

**规则**:
```python
def auto_assign_port(existing_instances):
    base_port = 18800
    step = 100
    
    used_ports = [inst.port for inst in existing_instances]
    
    port = base_port
    while port in used_ports:
        port += step
    
    return port
```

**说明**:
- 起始端口：18800
- 递增步长：100
- 自动避开已用端口

---

#### 决策 4: 实例命名

**规则**:
```python
def auto_generate_name(scenario, existing_names):
    prefix = 'openclaw'
    
    # 根据场景选择中缀
    if scenario in ['客服', '咨询']:
        middle = 'service'
    elif scenario in ['技术', '支持']:
        middle = 'tech'
    elif scenario in ['通知', '推送']:
        middle = 'notify'
    else:
        middle = 'default'
    
    # 自动递增序号
    num = 1
    while f"{prefix}-{middle}-{num:02d}" in existing_names:
        num += 1
    
    return f"{prefix}-{middle}-{num:02d}"
```

**示例**:
- 客服机器人：`openclaw-service-01`
- 技术支持：`openclaw-tech-01`
- 通知助手：`openclaw-notify-01`

---

#### 决策 5: 日志级别

**规则**:
```python
def auto_select_log_level(environment):
    if environment == 'prod':
        return 'INFO'  # 生产：关键信息
    elif environment == 'test':
        return 'DEBUG'  # 测试：详细调试
    else:
        return 'INFO'  # 默认：关键信息
```

### 4.2 决策透明度

**原则**: 告诉用户"我帮你决定了什么"

**✅ 好的示例**:

```
AI: "✅ 我已经为你自动配置：

```

## 5. 错误处理设计

### 5.1 友好错误原则

**❌ 技术化错误（不好）**:
```
Error: models.providers.bailian: Unrecognized keys: "id"
at line 45 in openclaw.json
```

**✅ 友好错误（好）**:
```
😊 发现配置问题：
   模型配置中有些字段不被 OpenClaw 识别。
   
   别担心！我已经自动修复了。
   
   💡 提示：OpenClaw 对配置格式有严格要求，
   我会自动帮你检查和修复。
```

---

### 5.2 错误处理模板

#### 模板 1: 配置错误

```markdown
😊 发现【问题类型】：
   【问题描述（用户友好）】
   
   【解决方案】
   
   💡 提示：【预防措施】
```

#### 模板 2: 操作失败

```markdown
😊 【操作】遇到问题：
   【原因（用户友好）】
   
   我帮你【自动处理方案】
   
   要继续吗？（说"是"或"换个方式"）
```

#### 模板 3: 缺少信息

```markdown
😊 还差一步！需要【信息名称】。
   
   🔗 获取方式:
   【步骤1】
   【步骤2】
   
   💡 【格式提示】
```

---

### 5.3 错误分级

**P0 - 阻塞性错误**（必须解决）:
- 缺少必需信息（App ID等）
- 配置格式错误
- 服务无法启动

**处理**: 明确告知 + 提供解决方案 + 等待修复

**P1 - 警告性错误**（可继续）:
- 端口冲突（可换端口）
- 默认配置缺失（可使用其他）

**处理**: 提示问题 + 提供替代方案 + 自动处理

**P2 - 提示性信息**（不影响）:
- 性能建议
- 配置优化建议

**处理**: 友好提示 + 可选操作

---

### 5.4 错误恢复

**自动恢复**:
```
问题: 端口 18800 已被占用
处理: 自动分配 18900
反馈: "端口 18800 已被占用，我帮你换成了 18900"
```

**引导恢复**:
```
问题: App ID 格式错误
处理: 说明正确格式 + 示例
反馈: "App ID 格式: cli_xxxxxxxx，请重新提供"
```
