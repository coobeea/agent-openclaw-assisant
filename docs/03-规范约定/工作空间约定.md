# 🏗️ 工作空间约定

> **核心原则**: 生产用 `workspace`，测试用 `test-workspace`

---

## 📋 约定规则

### 1. 默认配置（生产环境）

**配置**: `shared/configs/global.yaml`

```yaml
global:
  workspace_root: "./workspace"  # 默认使用 workspace
```

**使用场景**: 
- ✅ 实际生产使用
- ✅ 正式部署的龙虾实例
- ✅ 长期运行的服务

**工作空间结构**:
```
workspace/
├── lobsters/       # 龙虾实例目录
├── data/           # 实例记录、配置数据
└── logs/           # 运行日志
```

---

### 2. 测试环境（临时覆盖）

**方式1: 环境变量覆盖（推荐）**

```bash
# 运行测试时使用 test-workspace
export OPENCLAW_ASSISTANT_WORKSPACE=./test-workspace
python3 scripts/orchestrator.py 创建一个龙虾
```

**方式2: 临时修改配置文件**

```yaml
global:
  workspace_root: "./test-workspace"  # 仅测试时
```

**使用场景**:
- ✅ 开发测试
- ✅ 功能验证
- ✅ 端到端测试
- ✅ 不影响生产数据

**工作空间结构**:
```
test-workspace/
├── lobsters/       # 测试龙虾实例
├── data/           # 测试数据（可随时清空）
└── logs/           # 测试日志
```

---

## 🔄 环境变量优先级

PathManager 的配置读取优先级：

```
1. 环境变量 OPENCLAW_ASSISTANT_WORKSPACE （最高优先级）
   ↓
2. global.yaml 配置
   ↓
3. 默认值 ./workspace
```

**示例**:

```bash
# 查看当前配置
python3 shared/configs/path_manager.py

# 使用测试环境
export OPENCLAW_ASSISTANT_WORKSPACE=./test-workspace
python3 shared/configs/path_manager.py  # 会显示 test-workspace

# 取消覆盖，恢复默认
unset OPENCLAW_ASSISTANT_WORKSPACE
python3 shared/configs/path_manager.py  # 会显示 workspace
```

## 🎯 实际使用示例

### 场景1: 生产部署

```bash
# 1. 确保使用 workspace（默认配置）
cd agent-openclaw-assisant

# 2. 创建生产龙虾
python3 scripts/orchestrator.py 创建飞书客服机器人

# 3. 查看实例（在 workspace/lobsters/ 下）
ls workspace/lobsters/
```

### 场景2: 开发测试

```bash
# 1. 设置测试环境变量
export OPENCLAW_ASSISTANT_WORKSPACE=./test-workspace

# 2. 运行测试
python3 scripts/orchestrator.py 创建测试龙虾

# 3. 测试完成后清空（不影响生产）
rm -rf test-workspace/lobsters/*
rm -rf test-workspace/logs/*
echo '{}' > test-workspace/data/agents.jsonl

# 4. 恢复正常环境
unset OPENCLAW_ASSISTANT_WORKSPACE
```

### 场景3: CI/CD 自动化测试

```yaml
# .github/workflows/test.yml
steps:
  - name: Run Tests
    env:
      OPENCLAW_ASSISTANT_WORKSPACE: ./test-workspace
    run: |
      python3 -m pytest tests/
      python3 scripts/orchestrator.py 创建一个龙虾
```

## ⚠️ 重要提醒

### ❌ 不要做的事

1. **不要在 global.yaml 中硬编码 test-workspace**
   ```yaml
   # ❌ 错误
   workspace_root: "./test-workspace"  # 这会影响生产使用
   ```

2. **不要在生产环境设置测试变量**
   ```bash
   # ❌ 错误：生产服务器上不要这样做
   export OPENCLAW_ASSISTANT_WORKSPACE=./test-workspace
   ```

3. **不要混用两个工作空间**
   - 生产龙虾在 `workspace/`
   - 测试龙虾在 `test-workspace/`
   - **不要在同一时间同时操作两个空间**

### ✅ 应该做的事

1. **默认配置保持 workspace**
   ```yaml
   # ✅ 正确
   workspace_root: "./workspace"
   ```

2. **测试时使用环境变量**
   ```bash
   # ✅ 正确：测试时临时覆盖
   OPENCLAW_ASSISTANT_WORKSPACE=./test-workspace python3 xxx.py
   ```

3. **测试脚本中显式声明**
   ```python
   # ✅ 正确：测试脚本开头设置
   import os
   os.environ['OPENCLAW_ASSISTANT_WORKSPACE'] = './test-workspace'
   ```

## 🔧 快速切换命令

### 切换到测试环境

```bash
export OPENCLAW_ASSISTANT_WORKSPACE=./test-workspace
```

### 恢复生产环境

```bash
unset OPENCLAW_ASSISTANT_WORKSPACE
```

### 一次性测试命令

```bash
# 不影响当前 shell 环境
OPENCLAW_ASSISTANT_WORKSPACE=./test-workspace python3 scripts/orchestrator.py 创建龙虾
```
