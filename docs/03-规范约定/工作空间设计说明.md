# 工作空间设计说明

## 🎯 设计要点总结

根据项目需求，工作空间的设计遵循以下关键原则：

### 1. 路径可配置 ✅

**不写死路径，支持灵活配置：**

```yaml
# shared/configs/global.yaml
global:
  workspace_root: "./workspace"              # 方式1：相对路径
  # workspace_root: "/data/openclaw"         # 方式2：绝对路径
  # workspace_root: "~/openclaw-instances"   # 方式3：用户目录
```

**在代码中的实现：**

```python
# ✅ 正确：从配置读取
from shared.utils.common import OpenClawUtils

utils = OpenClawUtils()
config = utils.get_global_config()
workspace_root = config['global']['workspace_root']  # 动态获取

# ❌ 错误：硬编码
workspace_root = "./workspace"  # 不要这样！
```

---

### 2. 结构不预定义 ✅

**我们只管理目录位置，不管理内部结构：**

```
workspace/
├── openclaw-prod-01/           # ✅ 我们创建这个目录
│   └── (OpenClaw 自己管理)     # ⚠️ 内部结构由 OpenClaw 决定
│
├── openclaw-dev-01/            # ✅ 我们创建这个目录  
│   └── (OpenClaw 自己管理)     # ⚠️ 内部结构由 OpenClaw 决定
```

**为什么不预定义内部结构？**

1. **版本差异**: 不同版本的 OpenClaw 可能使用不同的目录结构
2. **配置差异**: 不同配置可能产生不同的文件组织
3. **灵活性**: OpenClaw 可能更新其数据存储方式
4. **保真性**: 我们不对 OpenClaw 的实现做假设

---

### 3. 通过命令行操作 ✅

**使用 OpenClaw 命令行工具，不直接操作文件：**

```bash
# ✅ 正确：使用 OpenClaw 命令
openclaw init --workspace "$workspace_root/$instance_id"
openclaw config --workspace "$instance_path" get key
openclaw logs --workspace "$instance_path"

# ❌ 错误：直接操作文件
# cat "$instance_path/config/openclaw.yaml"
# echo "key=value" >> "$instance_path/config/settings.conf"
```

**为什么？**
- 保持与 OpenClaw 的兼容性
- OpenClaw 可能有验证和处理逻辑
- 配置格式可能在版本间变化

## 🛠️ 实现细节

### common.py 工具函数

```python
class OpenClawUtils:
    def __init__(self, workspace_root: str = "./workspace"):
        # workspace_root 应该从配置读取，不硬编码
        self.workspace_root = Path(workspace_root)
    
    def ensure_workspace_exists(self, instance_id: str) -> Path:
        """
        确保实例工作空间目录存在
        
        注意：只创建顶层目录，不创建内部结构
        """
        instance_path = self.get_instance_path(instance_id)
        instance_path.mkdir(parents=True, exist_ok=True)
        return instance_path  # 返回路径，供后续使用
```

**关键改进：**
- ✅ 函数名从 `ensure_workspace_structure` 改为 `ensure_workspace_exists`
- ✅ 只创建实例目录，不创建 config/, data/, logs/ 等子目录
- ✅ 返回路径，供调用 OpenClaw 命令时使用

---

### logger.py 日志工具

```python
def get_instance_logger(
    instance_id: str,
    workspace_root: Optional[Path] = None,  # 从配置传入
    ...
):
    """
    获取实例日志 logger
    
    注意：日志路径不硬编码，从参数传入
    如果 OpenClaw 有自己的日志系统，可能不需要我们的 logger
    """
    if workspace_root:
        # 尝试在实例目录下写日志（如果存在 logs/ 目录）
        log_dir = workspace_root / instance_id / "logs"
        if log_dir.exists():  # 只在目录存在时写入
            log_file = log_dir / "openclaw.log"
    ...
```

**关键改进：**
- ✅ `workspace_root` 作为参数传入，不硬编码
- ✅ 检查 `logs/` 目录是否存在再写入
- ✅ 如果目录不存在，只输出到控制台

```

│  1. 决定内部目录结构                        │
│  2. 创建所需的子目录                        │
│  3. 管理配置、数据、日志                    │

```
