# 工作空间管理说明

## 📂 工作空间概念

### 什么是工作空间？

工作空间（Workspace）是 OpenClaw 实例运行时存储数据的目录。每个 OpenClaw 实例都需要一个独立的工作空间来存储：
- 配置文件
- 运行数据
- 日志文件
- 插件数据
- 其他 OpenClaw 需要的文件

### 我们的职责

本技能包项目的职责是：

✅ **我们负责的：**
- 提供统一的工作空间根目录
- 为每个实例创建顶层目录（如 `workspace/openclaw-prod-01/`）
- 将实例的工作空间路径指向我们的目录
- 确保工作空间不被提交到 Git

❌ **我们不负责的：**
- 定义实例内部的目录结构
- 创建实例内部的子目录
- 管理实例内部的文件组织

> **重要原则**：实例内部的目录结构由 OpenClaw 自己创建和管理，我们不做任何假设或预定义。

## ⚙️ 路径配置

### 配置工作空间路径

工作空间路径通过 `shared/configs/global.yaml` 配置：

```yaml
global:
  workspace_root: "./workspace"    # 可配置，不写死
```

### 支持的路径格式

| 格式 | 示例 | 说明 |
|------|------|------|
| **相对路径** | `./workspace` | 相对于项目根目录 |
| **绝对路径** | `/data/openclaw/workspace` | 系统绝对路径 |
| **用户目录** | `~/openclaw-data` | 相对于用户主目录 |

### 路径选择建议

**开发环境：**
```yaml
workspace_root: "./workspace"
```
- 优点：方便管理，与项目在一起
- 缺点：可能占用项目目录空间

**生产环境：**
```yaml
workspace_root: "/data/openclaw/workspace"
```
- 优点：数据与代码分离，便于管理大量数据
- 缺点：需要配置目录权限

**个人使用：**
```yaml
workspace_root: "~/openclaw-instances"
```
- 优点：存储在用户目录，权限清晰
- 缺点：多用户环境需要各自配置

## 🏗️ 工作空间创建流程

### 创建实例时

```
1. 读取 global.yaml 获取 workspace_root
   ↓
2. 创建实例目录: {workspace_root}/{instance_id}/
   ↓
3. 调用 OpenClaw 命令，指定工作空间路径
   例如: openclaw init --workspace {workspace_root}/{instance_id}
   ↓
4. OpenClaw 自动创建内部所需的目录和文件
   ↓
5. 完成
```

### 代码示例

```python
from shared.utils.common import OpenClawUtils

utils = OpenClawUtils()

# 获取配置的工作空间路径（不硬编码）
config = utils.get_global_config()
workspace_root = config['global']['workspace_root']

# 创建实例顶层目录
instance_id = "openclaw-prod-01"
instance_path = utils.ensure_workspace_exists(instance_id)

# 调用 OpenClaw 命令，指定工作空间
# OpenClaw 会自动创建内部结构
utils.run_command([
    "openclaw", "init",
    "--workspace", str(instance_path),
    "--name", instance_id
])
```

## 🔐 安全和隐私

### Git 忽略规则

整个 `workspace/` 目录已在 `.gitignore` 中配置：

```gitignore
# OpenClaw 工作空间（包含所有运行数据）
workspace/
```

### 为什么要排除 workspace/？

1. **隐私保护**: 包含对话记录、用户数据
2. **敏感信息**: 包含 API 密钥、Token
3. **文件大小**: 运行数据可能很大
4. **个人化数据**: 每个人的实例配置不同

### 备份建议

虽然不提交到 Git，但应该定期备份：

```bash
# 备份整个工作空间
tar -czf openclaw-backup-$(date +%Y%m%d).tar.gz workspace/

# 备份单个实例
tar -czf openclaw-prod-01-backup-$(date +%Y%m%d).tar.gz workspace/openclaw-prod-01/
```

## 📊 工作空间管理

### 查看工作空间大小

```bash
# 查看总大小
du -sh workspace/

# 查看各实例大小
du -sh workspace/openclaw-*/
```

### 清理工作空间

```bash
# 清理测试实例
rm -rf workspace/openclaw-test-*

# 清理特定实例
rm -rf workspace/openclaw-old-instance
```

**注意**: 清理前请确认数据已备份！

## ⚠️ 注意事项

### 不要做的事

1. ❌ 不要假设实例内部有 `config/` 目录
2. ❌ 不要假设实例内部有 `data/` 目录
3. ❌ 不要假设实例内部有 `logs/` 目录
4. ❌ 不要直接修改实例内部的文件
5. ❌ 不要在代码中硬编码工作空间路径

### 应该做的事

1. ✅ 从配置文件读取 `workspace_root`
2. ✅ 只创建实例的顶层目录
3. ✅ 使用 OpenClaw 命令行工具操作实例
4. ✅ 通过 OpenClaw API 获取实例信息
5. ✅ 保持对 OpenClaw 内部实现的零假设

## 🎯 技能包实现指导

### openclaw-manager 技能包

在创建实例时：

```bash
# 1. 读取配置的工作空间路径
workspace_root=$(yq .global.workspace_root global.yaml)

# 2. 创建实例目录
mkdir -p "$workspace_root/$instance_id"

# 3. 调用 OpenClaw 初始化（指定工作空间）
openclaw init \
  --workspace "$workspace_root/$instance_id" \
  --name "$instance_id"

# 4. OpenClaw 会自动创建它需要的内部结构
```

### 其他技能包

在操作实例时：

```bash
# 获取实例路径
instance_path="$workspace_root/$instance_id"

# 使用 OpenClaw 命令操作，不直接操作文件
openclaw config --workspace "$instance_path" --set key=value
openclaw plugin --workspace "$instance_path" install feishu
openclaw channel --workspace "$instance_path" add ...
```
