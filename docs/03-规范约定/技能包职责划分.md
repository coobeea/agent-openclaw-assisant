# 技能包职责划分

> 明确各技能包的职责边界，避免功能重叠和架构混乱

---

## 🎯 核心原则

### 1. 职责单一

每个技能包只负责一个领域的功能，不跨界。

### 2. 技能包自包含

所有功能相关的脚本、配置、文档都在技能包目录内。

### 3. 项目根目录保持清洁

**不在根目录放置业务逻辑脚本**，只保留：
- ✅ README.md / AGENTS.md 等文档
- ✅ requirements.txt / .gitignore 等配置
- ✅ skills/ docs/ 等目录结构
- ❌ 业务逻辑脚本（应放在对应技能包内）

### 4. 跨平台支持

技能包必须同时支持 macOS/Linux 和 Windows：
- 提供 `.sh` 和 `.bat` 两种脚本
- 或使用 Python 等跨平台语言

**这是项目的环境验证中心，所有环境相关的检查都在这里！**

**触发时机**:
- 首次使用项目
- 虚拟环境不存在
- 执行 Python 脚本前检查

## 🚨 常见错误示例

### ❌ 错误 1：在根目录创建业务脚本

```
agent-openclaw-assisant/
├── check_venv.sh        # ❌ 环境检查应在 env-checker 中
├── verify.sh            # ❌ 验证脚本应在 env-checker 中
├── example_usage.sh     # ❌ 业务逻辑不应在根目录
├── README.md            # ✅ 文档可以
└── skills/
    └── env-checker/
        └── scripts/
            └── setup.sh # ✅ 业务逻辑应在这里
```

**问题**:
1. 根目录混乱，难以维护
2. 职责不清晰
3. 违反单一职责原则
4. 通常只支持 Unix/Linux，缺少 Windows 支持

### ❌ 错误 2：创建跨平台不兼容的脚本

```bash
#!/bin/bash              # ❌ Windows 无法运行
# verify.sh - 只在 macOS/Linux 上工作
```

**问题**:
1. 违反项目跨平台原则
2. Windows 用户无法使用
3. 与 env-checker 的设计理念相悖

### ❌ 错误 3：静态文件检查而非环境检查

```bash
# verify.sh 检查的内容
if [ -d "skills" ]; then  # ❌ Git 已经保证文件完整性
    echo "✅ skills/ 存在"
fi

if [ -f "README.md" ]; then  # ❌ 无意义的检查
    echo "✅ README.md 存在"
fi
```

**问题**:
1. 检查文件是否存在毫无意义（Git 已保证）
2. 没有检查真正重要的：环境是否可用
3. 应该检查：Python 版本、虚拟环境、依赖库

---

### ✅ 正确：功能归属对应技能包

```
agent-openclaw-assisant/
├── README.md            # ✅ 项目文档
├── AGENTS.md            # ✅ AI 规则
└── skills/
    └── env-checker/     # ✅ 环境检查功能归这里
        ├── SKILL.md
        └── scripts/
            ├── check.sh     # ✅ 检查功能
            ├── check.bat    # ✅ 跨平台支持
            ├── setup.sh     # ✅ 初始化功能
            └── setup.bat    # ✅ 跨平台支持
```

**优点**:
1. 职责清晰
2. 易于维护
3. 支持跨平台

## 📋 添加新功能的检查清单

当你需要添加新功能时，问自己：

### 1. 功能归属

- [ ] 这个功能属于哪个技能包？
- [ ] 是否需要创建新的技能包？
- [ ] 是否跨越了多个技能包的职责？

### 2. 跨平台支持

- [ ] 是否同时提供了 `.sh` 和 `.bat`？
- [ ] 或者使用了 Python 等跨平台语言？
- [ ] 是否在多个平台上测试过？

### 3. 目录位置

- [ ] 脚本是否放在对应技能包的 `scripts/` 目录下？
- [ ] 文档是否放在对应技能包的根目录或 `docs/`？
- [ ] 是否避免了在项目根目录添加业务脚本？

### 4. 依赖关系

- [ ] 是否明确了依赖的其他技能包？
- [ ] 是否更新了 `SKILLS_MANIFEST.yaml`？
- [ ] 是否在 `SKILL.md` 中说明了依赖？

### 5. 文档更新

- [ ] 是否更新了技能包的 `SKILL.md`？
- [ ] 是否更新了 `AGENTS.md`（如需要）？
- [ ] 是否更新了项目 `README.md`（如需要）？

## 🎯 最佳实践

### 1. 环境验证的正确方式

**✅ 正确**：使用 env-checker 技能包

```bash
# 第一步：检查虚拟环境（跨平台）
# macOS/Linux
bash skills/env-checker/scripts/check.sh

# Windows
skills\env-checker\scripts\check.bat

# 第二步：根据结果决定
if [ $? -eq 0 ]; then
    # 虚拟环境存在，使用它
    eval "$(bash skills/env-checker/scripts/check.sh)"
    $VENV_PYTHON skills/openclaw-manager/scripts/instance_manager.py list
else
    # 虚拟环境不存在，创建它
    bash skills/env-checker/scripts/setup.sh
fi

# 第三步：验证依赖库
$VENV_PYTHON skills/env-checker/scripts/verify.py
```

**❌ 错误**：创建独立的 verify.sh

```bash
# ❌ 不要这样做
./verify.sh  # 只检查文件是否存在，毫无意义
```

**为什么错误**:
1. Git 已经保证文件完整性
2. 不是跨平台的
3. 没有检查真正重要的环境可用性
4. 违反技能包职责划分原则

### 2. AI 助手工作流

```
Step 1: 检查虚拟环境
  执行: bash skills/env-checker/scripts/check.sh
  职责: env-checker 技能包

Step 2: 检查实例列表
  执行: $VENV_PYTHON skills/openclaw-manager/scripts/instance_manager.py list
  职责: openclaw-manager 技能包

Step 3: 配置渠道
  执行: $VENV_PYTHON skills/openclaw-channel/scripts/channel_manager.py add ...
  职责: openclaw-channel 技能包
```

**关键**: 每个步骤使用对应技能包的功能，职责清晰。
