### 核心接口

```go
// KernelInterface - 统一内核接口
type KernelInterface interface {
    Initialize(ctx context.Context, config *KernelConfig) error
    StreamChat(ctx context.Context, req *ChatRequest) (<-chan ChatEvent, error)
    CreateAgent(ctx context.Context, agentID, workspace string) error
    HealthCheck(ctx context.Context) error
    Close() error
    GetKernelType() string
}

// ChatRequest - 统一请求格式
type ChatRequest struct {
    AgentID    string
    SessionKey string
    Message    string
    UserID     string
    RequestID  string
}

// ChatEvent - 统一事件格式
type ChatEvent struct {
    Type      string  // "delta" | "done" | "error" | "start"
    Content   string
    SessionKey string
    Error     string
    Timestamp time.Time
}
```

## 🔧 使用方式

### 方式 1：使用默认内核（OpenClaw）

```bash
curl -X POST http://localhost:30080/api/chat/stream/v2 \
  -H "Content-Type: application/json" \
  -d '{
    "agent_id": "test",
    "message": "Hello, World!"
  }'
```

### 方式 2：通过 HTTP Header 切换内核

```bash
# 使用 QwenPaw
curl -X POST http://localhost:30080/api/chat/stream/v2 \
  -H "Content-Type: application/json" \
  -H "X-Kernel-Type: qwenpaw" \
  -d '{
    "agent_id": "test",
    "message": "Hello, QwenPaw!"
  }'

# 使用 OpenClaw
curl -X POST http://localhost:30080/api/chat/stream/v2 \
  -H "Content-Type: application/json" \
  -H "X-Kernel-Type: openclaw" \
  -d '{
    "agent_id": "test",
    "message": "Hello, OpenClaw!"
  }'
```

### 方式 3：修改全局配置

```bash
# 编辑 ConfigMap
kubectl edit configmap scheduler-config -n openclaw

# 修改 KERNEL_TYPE
data:
  KERNEL_TYPE: "qwenpaw"  # "openclaw" | "qwenpaw"

# 重启 Scheduler
kubectl delete pod -n openclaw -l app=openclaw-scheduler
```

## 📈 性能对比

### 连接建立时间

| 内核 | 握手时间 | 连接类型 | 持久化 |
|------|---------|---------|--------|
| **OpenClaw** | ~500ms | WebSocket | ✅ |
| **QwenPaw** | ~200ms | HTTP | ❌ |

### 流式性能

| 指标 | OpenClaw | QwenPaw |
|------|----------|---------|
| **首字延迟** | ~1-2s | ~1-2s |
| **吞吐量** | 高（全双工） | 中（单向） |
| **并发能力** | 优秀 | 良好 |
| **资源占用** | 低 | 中 |

### 建议

- **实时性要求高** → 选择 OpenClaw
- **兼容性要求高** → 选择 QwenPaw  
- **Python AI/ML 生态** → 选择 QwenPaw
- **生产环境稳定性** → 选择 OpenClaw

## 🐛 已知问题和限制

### 1. Agent 注册

**问题**：QwenPaw 的 Agent 注册逻辑可能与 OpenClaw 不同

**解决方案**：
- 在 `QwenPawAdapter.CreateAgent` 中实现适配逻辑
- 或依赖 QwenPaw 的配置文件管理

### 2. 会话管理

**问题**：两种内核的会话管理机制不同

**解决方案**：
- 使用统一的 `sessionKey` 格式
- Scheduler 负责会话映射和转换

### 3. 性能开销

**问题**：抽象层引入了轻微性能开销

**影响**：每次请求增加 ~10-20ms

**缓解**：
- 连接池复用
- 减少不必要的序列化/反序列化
