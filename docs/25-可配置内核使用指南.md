# 可配置内核使用指南

> **功能**：支持在 OpenClaw 和 QwenPaw 之间灵活切换  
> **版本**：Scheduler V2 API  
> **状态**：✅ 已实现并测试

---

## 🎯 核心特性

### 双内核支持

| 内核 | 协议 | 端口 | 特点 |
|------|------|------|------|
| **OpenClaw** | WebSocket | 18789 | 实时性强，官方支持 |
| **QwenPaw** | HTTP + SSE | 8088 | Python 生态，多智能体协作 |

### 切换方式

1. **全局切换**（环境变量）
2. **动态切换**（HTTP Header）

---

## 🚀 快速开始

### 方式 1：使用默认内核（OpenClaw）

```bash
# 默认使用 OpenClaw
curl -X POST http://localhost:30080/api/chat/stream/v2 \
  -H "Content-Type: application/json" \
  -d '{
    "agent_id": "test-agent",
    "message": "Hello, OpenClaw!"
  }'
```

### 方式 2：通过 HTTP Header 切换内核

```bash
# 使用 QwenPaw
curl -X POST http://localhost:30080/api/chat/stream/v2 \
  -H "Content-Type: application/json" \
  -H "X-Kernel-Type: qwenpaw" \
  -d '{
    "agent_id": "test-agent",
    "message": "Hello, QwenPaw!"
  }'

# 使用 OpenClaw（显式指定）
curl -X POST http://localhost:30080/api/chat/stream/v2 \
  -H "Content-Type: application/json" \
  -H "X-Kernel-Type: openclaw" \
  -d '{
    "agent_id": "test-agent",
    "message": "Hello, OpenClaw!"
  }'
```

### 方式 3：修改全局配置（K8s ConfigMap）

```bash
# 编辑配置
kubectl edit configmap scheduler-config -n openclaw

# 修改 KERNEL_TYPE
data:
  KERNEL_TYPE: "qwenpaw"  # 改为 "openclaw" 或 "qwenpaw"

# 重启 Scheduler
kubectl delete pod -n openclaw -l app=openclaw-scheduler
```

## 📡 API 接口

### V2 流式聊天接口（可配置内核）

**端点**: `POST /api/chat/stream/v2`

**Headers**:
```
Content-Type: application/json
X-Kernel-Type: openclaw  # 可选: "openclaw" | "qwenpaw"
```

**Request Body**:
```json
{
  "agent_id": "test-agent",
  "message": "你好，请介绍一下自己"
}
```

**Response**（SSE 流）:
```
: connected

data: {"type":"delta","content":"你好"}
data: {"type":"delta","content":"！我是"}
data: {"type":"delta","content":"一个AI助手"}
data: {"type":"done"}
```

### 响应头说明

- `Content-Type: text/event-stream` - SSE 流
- `X-Kernel-Type: openclaw` - 实际使用的内核类型

## 🔧 配置说明

### 环境变量（ConfigMap）

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: scheduler-config
  namespace: openclaw
data:
  # 全局默认内核
  KERNEL_TYPE: "openclaw"
  
  # OpenClaw 配置
  KERNEL_OPENCLAW_AUTH_TOKEN: "openclaw-internal-k8s-token"
  
  # QwenPaw 配置（可选）
  KERNEL_QWENPAW_AUTH_TOKEN: ""
```

### 内核特定配置

#### OpenClaw

```go
// 代码中自动应用的配置
config := kernel.DefaultOpenClawConfig(podIP, authToken)
config.Timeout = 120  // 2分钟超时
config.Extra["protocol"] = "websocket"
config.Extra["port"] = "18789"
```

#### QwenPaw

```go
// 代码中自动应用的配置
config := kernel.DefaultQwenPawConfig(fmt.Sprintf("%s:8088", podIP))
config.Timeout = 120  // 2分钟超时
config.Extra["protocol"] = "http"
config.Extra["port"] = "8088"
```

## 🏗️ 部署架构

### 混合部署（推荐）

```
Frontend (Vue3)
    ↓ HTTP/SSE
Scheduler (Go)
    ├─> OpenClaw Pods (3个)
    └─> QwenPaw Pods (2个)
```

**部署步骤**:

```bash
# 1. 部署 OpenClaw 池
kubectl apply -f k8s-manifests/04-openclaw-pool.yaml

# 2. 部署 QwenPaw 池（如需要）
kubectl apply -f k8s-manifests/07-qwenpaw-pool.yaml

# 3. 部署 Scheduler（支持双内核）
kubectl apply -f k8s-manifests/05-scheduler-configurable-kernel.yaml

# 4. 部署 Frontend
kubectl apply -f k8s-manifests/06-frontend.yaml
```

### 单内核部署

```bash
# 只部署 OpenClaw
kubectl apply -f k8s-manifests/04-openclaw-pool.yaml
kubectl apply -f k8s-manifests/05-scheduler-configurable-kernel.yaml

# 环境变量确保设置为 openclaw
kubectl set env deployment/openclaw-scheduler KERNEL_TYPE=openclaw -n openclaw
```

## 📊 性能对比

| 指标 | OpenClaw | QwenPaw |
|------|----------|---------|
| **连接建立** | ~500ms (WebSocket握手) | ~200ms (HTTP连接) |
| **首字延迟** | ~1-2s | ~1-2s |
| **流式吞吐** | 高（WebSocket全双工） | 中（HTTP单向） |
| **并发支持** | 优秀（持久连接） | 良好（HTTP连接池） |
| **资源占用** | 低（单连接复用） | 中（多连接） |

**建议**：
- **实时性要求高** → 选择 OpenClaw
- **兼容性要求高** → 选择 QwenPaw
- **Python AI/ML 集成** → 选择 QwenPaw

## 🐛 故障排查

### 问题 1：内核切换不生效

**症状**：设置了 `X-Kernel-Type: qwenpaw` 但仍使用 OpenClaw

**解决**：
```bash
# 1. 检查 QwenPaw Pod 是否运行
kubectl get pods -n openclaw -l app=qwenpaw-pool

# 2. 检查 Scheduler 日志
kubectl logs deployment/openclaw-scheduler -n openclaw | grep "使用内核"

# 3. 验证 Header 是否正确传递
curl -v -H "X-Kernel-Type: qwenpaw" http://localhost:30080/api/chat/stream/v2
```

### 问题 2：QwenPaw 连接失败

**症状**：`HTTP 503` 或 `没有可用的容器`

**解决**：
```bash
# 1. 检查 QwenPaw Pod
kubectl get pods -n openclaw -l app=qwenpaw-pool
kubectl describe pod <qwenpaw-pod-name> -n openclaw

# 2. 检查端口
kubectl exec -it <qwenpaw-pod-name> -n openclaw -- netstat -tuln | grep 8088

# 3. 测试健康检查
kubectl exec -it <qwenpaw-pod-name> -n openclaw -- curl http://localhost:8088/api/version
```

### 问题 3：编译失败

**症状**：`package openclaw-scheduler/internal/kernel not found`

**解决**：
```bash
cd scheduler-go
go mod tidy
go build -o bin/scheduler cmd/server/main.go
```

## 🔄 版本兼容性

### V1 API（原版）

```bash
# 仍然可用，直接使用 WebSocket
POST /api/chat/stream
```

**特点**：
- ✅ 保持向后兼容
- ✅ 性能优化（直接 WebSocket）
- ❌ 不支持内核切换

### V2 API（新版）

```bash
# 支持可配置内核
POST /api/chat/stream/v2
```

**特点**：
- ✅ 支持双内核切换
- ✅ 统一接口抽象
- ✅ 更好的扩展性
- ⚠️  略微性能开销（抽象层）

**建议**：新项目使用 V2 API
