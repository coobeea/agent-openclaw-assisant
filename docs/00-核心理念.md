# OpenClaw 核心理念：灵魂与载体分离

## 🎯 核心哲学

> **灵魂永恒，载体无常**  
> Soul is eternal, Vessel is ephemeral

受 Vessel 项目启发，OpenClaw 采用"灵魂-载体分离"架构，实现真正的多租户智能体 SaaS 平台。

---

## 一、核心概念

### 1.1 灵魂（Soul）- 智能体的本质

**定义**：智能体的持久化数据，包含配置、记忆、知识和状态。

**组成部分**：
```
/data/agents/{agent_id}/          # 智能体的灵魂空间
├── config.json                   # 配置文件（模型、参数）
├── chats/                        # 对话记忆
│   ├── session-xxx.json          # 会话记录
│   └── history.db                # 历史索引
├── files/                        # 知识库文件
│   ├── documents/                # 用户上传文档
│   └── generated/                # 生成的文件
└── state/                        # 运行状态
    ├── context.json              # 上下文状态
    └── variables.json            # 变量存储
```

**存储方式**：
- **元数据**：PostgreSQL（agent_id, name, workspace_path）
- **实际数据**：文件系统（hostPath/PVC）
- **缓存**：Redis（热数据、会话状态）

**特点**：
- ✅ 永久持久化，不随容器销毁而消失
- ✅ 用户私有，严格隔离
- ✅ 可备份、可迁移、可恢复
- ✅ 与执行环境解耦

---

### 1.2 载体（Vessel）- 临时的执行环境

**定义**：容器化的沙箱环境，作为智能体的临时"肉身"，负责执行任务。

**组成部分**：
```
┌─────────────────────────────────────┐
│  Kubernetes Pod（载体）             │
│  ┌───────────────────────────────┐ │
│  │ OpenClaw/QwenPaw 容器         │ │
│  │ - 挂载 /data/agents/{id}      │ │
│  │ - 读取 config.json            │ │
│  │ - 执行对话逻辑                │ │
│  │ - 调用 LLM API                │ │
│  └───────────────────────────────┘ │
└─────────────────────────────────────┘
```

**生命周期**：
1. **分配**：从热池（Hot Pool）中获取空闲容器
2. **绑定**：挂载智能体的灵魂空间（workspace）
3. **加载**：读取 config.json，初始化状态
4. **执行**：处理用户对话，调用工具
5. **回收**：用户离线后，清理并归还容器到热池

**特点**：
- ✅ 无状态，可随时销毁和重建
- ✅ 可复用，同一容器可服务不同智能体
- ✅ 资源隔离，CPU/内存限制
- ✅ 快速启动，3 秒内完成分配

## 二、架构优势

### 2.1 真正的多租户
```
灵魂层：每个用户拥有独立的 workspace
载体层：所有用户共享容器池
```

**好处**：
- 成本低：试用用户和付费用户共享底层资源
- 扩展强：容器池按需弹性伸缩
- 安全：数据隔离，容器销毁不影响数据

---

### 2.2 数据永久性
```
用户创建智能体 → 创建 workspace → 写入 config.json
用户对话 → 容器挂载 workspace → 读取配置 → 执行
用户离线 → 容器回收 → workspace 保留
用户再次上线 → 分配新容器 → 挂载同一 workspace → 继续对话
```

**好处**：
- 对话历史永不丢失
- 文件持久化存储
- 智能体配置可迁移

---

### 2.3 资源高效利用
```
热池机制：
  预热 N 个空闲容器
  需要时立即分配
  空闲后自动回收
  容器可复用
```

**好处**：
- 冷启动时间 < 3 秒
- 资源利用率高（共享容器池）
- 支持海量用户（10 万+ 用户共享 1000+ 容器）

## 三、实现细节

### 3.1 创建智能体（创建灵魂）
```python
# Scheduler 逻辑
def create_agent(user_id, name, kernel_type, model_config):
    # 1. 生成 agent_id
    agent_id = f"agent-{user_id}-{timestamp}"
    
    # 2. 创建灵魂空间（workspace）
    workspace_path = f"/data/agents/{agent_id}"
    os.makedirs(workspace_path, exist_ok=True)
    
    # 3. 写入配置文件（灵魂的核心）
    config = {
        "kernel_type": kernel_type,
        "model": model_config or default_model_config,
        "agent_info": {"name": name, "description": ...}
    }
    with open(f"{workspace_path}/config.json", "w") as f:
        json.dump(config, f)
    
    # 4. 保存元数据到数据库
    db.insert("agents", {
        "agent_id": agent_id,
        "user_id": user_id,
        "workspace_path": workspace_path
    })
    
    return agent_id
```

### 3.3 容器热池调度（载体管理）
```python
# Kubernetes 部署
apiVersion: apps/v1
kind: Deployment
metadata:
  name: openclaw-pool
spec:
  replicas: 10  # 热池大小
  template:
    spec:
      containers:
      - name: openclaw
        image: openclaw:latest
        volumeMounts:
        - name: agents-workspace  # 挂载所有灵魂空间
          mountPath: /data/agents
      volumes:
      - name: agents-workspace
        hostPath:
          path: /data/workspace  # Host 上的持久化目录
```

**热池逻辑**：
```python
class HotPool:
    def __init__(self):
        self.idle_containers = []  # 空闲容器队列
        self.active_sessions = {}  # agent_id -> container_id
    
    def allocate(self, kernel_type):
        # 从队列获取空闲容器
        container = self.idle_containers.pop(kernel_type)
        return container
    
    def release(self, container):
        # 清理容器状态
        container.reset()
        # 归还到空闲队列
        self.idle_containers.append(container)
```

## 六、设计原则

### 原则 1：灵魂优先（Soul First）
> 任何功能设计，都要先考虑"灵魂"（数据）是否持久化、是否安全隔离。

**示例**：
- ❌ 错误：把模型配置存在容器内部 → 容器销毁后配置丢失
- ✅ 正确：把模型配置写入 workspace/config.json → 容器销毁后可恢复

---

### 原则 2：载体无状态（Stateless Vessel）
> 容器应当是纯粹的执行环境，不保存任何用户数据。

**示例**：
- ❌ 错误：对话历史存在容器内存中 → 容器回收后历史丢失
- ✅ 正确：对话历史写入 workspace/chats/ → 容器回收后历史保留

---

### 原则 3：热池复用（Hot Pool Reuse）
> 容器应当可复用，避免频繁创建销毁。

**示例**：
- ❌ 错误：每次对话创建新容器 → 启动慢、资源浪费
- ✅ 正确：从热池获取空闲容器 → 3 秒内完成分配

---

### 原则 4：配置驱动（Configuration Driven）
> 智能体的行为由 config.json 驱动，容器只是执行者。

**示例**：
- ❌ 错误：硬编码模型配置在容器代码中
- ✅ 正确：容器启动时读取 workspace/config.json

## 八、总结

**OpenClaw 核心理念**：
```
灵魂（Soul）= 持久化数据（workspace）
载体（Vessel）= 临时容器（Pod）
热池（Hot Pool）= 容器复用机制
```

**架构优势**：
- 数据永久性：灵魂永存
- 资源高效：载体复用
- 成本优化：共享容器池
- 扩展性强：支持海量用户

**设计哲学**：
> **灵魂定义了智能体是什么，载体决定了智能体能做什么。**  
> 灵魂是本质，载体是工具。灵魂永恒，载体无常。
