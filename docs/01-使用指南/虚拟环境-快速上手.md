# 虚拟环境 - 快速上手 🚀

> **1分钟全自动创建项目虚拟环境（使用 env-checker）**

---

## 🎯 为什么需要虚拟环境？

**一句话**: 确保所有机器环境完全一致，避免依赖冲突。

**不使用的后果**:
- ❌ A机器能运行，B机器报错
- ❌ 依赖冲突导致莫名其妙的问题
- ❌ 系统Python环境被污染
- ❌ 系统可能没有Python

**使用 env-checker 的好处**:
- ✅ **自动检测和安装Python** - 系统没Python也能用！🌟
- ✅ 所有机器环境完全一致
- ✅ 隔离依赖，互不干扰
- ✅ 一键创建，全自动化
- ✅ 虚拟环境是隐藏目录（`.venv/`），不影响项目外观

## ❓ 常见问题

### Q1: 系统没有 Python 怎么办？

**不用担心！env-checker 会自动下载安装！** 🌟

```bash
# 直接运行，它会自动检测并安装Python 3.12
bash skills/env-checker/scripts/setup.sh

# 自动完成：
# 1. 检测系统Python
# 2. 如果没有，自动从 python.org 下载
# 3. 自动安装（macOS用brew或pkg，Windows用exe）
# 4. 创建虚拟环境
```

---

### Q2: 虚拟环境创建失败怎么办？

```bash
# 使用 --verbose 查看详细日志
bash skills/env-checker/scripts/setup.sh --verbose

# 检查磁盘空间
df -h

# 重新尝试
bash skills/env-checker/scripts/setup.sh
```

---

### Q3: 激活虚拟环境后，Python路径还是系统的？

```bash
# 检查虚拟环境是否存在
ls -la .venv/bin/python

# 如果不存在，重新创建
bash skills/env-checker/scripts/setup.sh

# 检查是否真的激活了
echo $VIRTUAL_ENV  # 应该输出 .venv 路径
```

---

### Q4: 忘记激活虚拟环境，直接运行脚本会怎样？

**不推荐**，但可以直接使用绝对路径：

```bash
# ✅ 推荐：直接使用虚拟环境Python（无需激活，AI助手方式）
.venv/bin/python skills/.../script.py

# ✅ 或先激活再运行
source .venv/bin/activate
python skills/.../script.py

# ❌ 避免：使用系统Python
python3 skills/.../script.py
```

---

### Q5: 虚拟环境占用多少空间？

约 **100-150 MB**（包含所有技能包依赖）

---

### Q6: 可以删除虚拟环境吗？

**可以**，虚拟环境是可重建的：

```bash
# 删除
rm -rf .venv/

# 重建（一键完成）
bash skills/env-checker/scripts/setup.sh
```

---

### Q7: 为什么是 `.venv` 而不是 `venv`？

- ✅ `.venv` 是隐藏目录（以点开头）
- ✅ 不会在 `ls` 中显示，保持项目目录整洁
- ✅ 不影响项目外观
- ✅ 是 Python 社区的推荐做法

## 💡 小技巧

### 技巧1: 设置环境变量（推荐）

添加到 `~/.bashrc` 或 `~/.zshrc`:

```bash
# 设置项目根目录
export OPENCLAW_ROOT="/path/to/agent-openclaw-assisant"

# 设置虚拟环境Python
export OPENCLAW_PYTHON="$OPENCLAW_ROOT/.venv/bin/python"

# 创建别名
alias openclaw='$OPENCLAW_PYTHON'
alias openclaw-venv='source $OPENCLAW_ROOT/.venv/bin/activate'
```

使用：
```bash
# 直接使用
openclaw skills/openclaw-manager/scripts/instance_manager.py list

# 或激活虚拟环境
openclaw-venv
python skills/openclaw-manager/scripts/instance_manager.py list
```

---

### 技巧2: 检查当前是否在虚拟环境中

```bash
# 方法1: 查看环境变量
echo $VIRTUAL_ENV  # 应该输出 .../.venv

# 方法2: 查看Python路径
which python  # 应该输出 .../.venv/bin/python

# 方法3: 查看提示符
# 激活后会显示 (.venv) 前缀
```

---

### 技巧3: 快速重建虚拟环境

```bash
# 一键删除并重建
rm -rf .venv/ && bash skills/env-checker/scripts/setup.sh
```

---

### 技巧4: 仅检查不安装

```bash
# 仅检查环境，不执行安装
bash skills/env-checker/scripts/setup.sh --check-only

# 会显示环境报告但不创建虚拟环境
```

## 🎯 记住这些

### ✅ 5个必须

1. **必须使用 env-checker 创建虚拟环境** - 项目初始化第一步
2. **必须使用 `.venv/bin/python` 执行脚本** - 明确指定虚拟环境
3. **虚拟环境目录是 `.venv`（隐藏目录）** - 不是 `venv`
4. **AI 助手必须使用绝对路径** - 避免歧义
5. **新依赖必须添加到 env-checker/requirements.txt** - 统一管理

### ❌ 5个禁止

1. **禁止在系统Python环境中运行项目脚本**
2. **禁止在虚拟环境外安装项目依赖**
3. **禁止在根目录创建 `venv/` 目录** - 使用 `.venv/`
4. **禁止绕过 env-checker 手动创建虚拟环境** - 会缺少自动检测和验证
5. **禁止在各个技能包的 requirements.txt 中添加依赖** - 统一在 env-checker 中管理
