# 容器自动释放实施方案

## 🎯 问题

当前实现中，容器被分配给 Agent 后永不释放，导致：
- 容器池很快耗尽
- 新请求返回 `{"error":"没有可用的容器"}`
- 用户体验极差（"从来没成功过"）

## ✅ 解决方案

### 方案 1: 超时自动释放（推荐）

在对话结束后，设置超时自动释放容器。

**实施步骤**：

#### 1. 修改 `PoolStatus` 结构

```go
// scheduler-go/internal/k8s/k8s.go
type PoolStatus struct {
    Status      string    `json:"status"`       // "idle" | "busy"
    AgentID     string    `json:"agent_id"`
    AllocatedAt time.Time `json:"allocated_at"` // 分配时间
    LastActivity time.Time `json:"last_activity"` // 最后活动时间
}
```

#### 2. 在 `ChatStream` 结束时更新活动时间

```go
// scheduler-go/internal/api/api.go
defer func() {
    // 对话结束时更新最后活动时间
    poolMu.Lock()
    if status, exists := poolStatus[container.PodName]; exists {
        status.LastActivity = time.Now()
        poolStatus[container.PodName] = status
    }
    poolMu.Unlock()
}()
```

#### 3. 添加自动清理 Goroutine

```go
// scheduler-go/cmd/server/main.go
func startContainerCleanup() {
    ticker := time.NewTicker(30 * time.Second) // 每30秒检查一次
    go func() {
        for range ticker.C {
            k8s.CleanupIdleContainers(5 * time.Minute) // 释放5分钟无活动的容器
        }
    }()
}

// 在 main 函数中启动
func main() {
    // ... 其他初始化 ...
    startContainerCleanup()
    // ...
}
```

#### 4. 实现清理函数

```go
// scheduler-go/internal/k8s/k8s.go
func CleanupIdleContainers(idleTimeout time.Duration) {
    poolMu.Lock()
    defer poolMu.Unlock()
    
    now := time.Now()
    released := 0
    
    for podName, status := range poolStatus {
        if status.Status == "busy" {
            // 检查是否超过空闲时间
            if now.Sub(status.LastActivity) > idleTimeout {
                log.Printf("🔄 [Cleanup] 释放空闲容器: %s (Agent: %s, 空闲: %.1f分钟)",
                    podName, status.AgentID, now.Sub(status.LastActivity).Minutes())
                
                status.Status = "idle"
                status.AgentID = ""
                status.LastActivity = time.Time{}
                poolStatus[podName] = status
                
                // 从 agentSessions 中删除
                delete(agentSessions, status.AgentID)
                
                released++
            }
        }
    }
    
    if released > 0 {
        log.Printf("✅ [Cleanup] 已释放 %d 个容器", released)
    }
}
```

### 方案 2: 对话结束立即释放

在每次对话结束时立即释放容器。

**优点**: 简单，响应快
**缺点**: 同一用户连续对话需要重新分配

**实施**：

```go
// scheduler-go/internal/api/api.go - ChatStream 函数末尾
defer func() {
    // 对话结束，释放容器
    k8s.ReleaseContainer(container.PodName, req.AgentID)
    log.Printf("🔄 [ChatStream] 容器已释放: %s", container.PodName)
}()
```

```go
// scheduler-go/internal/k8s/k8s.go
func ReleaseContainer(podName, agentID string) error {
    poolMu.Lock()
    defer poolMu.Unlock()
    
    if status, exists := poolStatus[podName]; exists && status.AgentID == agentID {
        status.Status = "idle"
        status.AgentID = ""
        status.LastActivity = time.Time{}
        poolStatus[podName] = status
        
        delete(agentSessions, agentID)
        
        log.Printf("✅ [K8s] 容器已释放: %s (Agent: %s)", podName, agentID)
        return nil
    }
    
    return fmt.Errorf("container not found or agent mismatch")
}
```

### 方案 3: 容器复用（最优但复杂）

同一 Agent ID 的请求复用已分配的容器。

**优点**: 性能最好，无重复启动
**缺点**: 实现复杂，需要状态管理

**实施要点**：
1. 检查 `agentSessions[agentID]` 是否已有分配
2. 如果有，复用该容器
3. 如果容器不可用（Pod 删除），重新分配
4. 超时后释放（结合方案 1）

## 🚀 推荐实施顺序

### 第一步：立即释放（临时）
实施方案 2，确保容器不会永久占用。

### 第二步：超时释放（稳定）
实施方案 1，提供更好的用户体验（连续对话无需重启Agent）。

### 第三步：智能复用（优化）
实施方案 3，达到生产级性能。
