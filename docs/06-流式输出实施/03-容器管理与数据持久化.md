# 容器管理与数据持久化详细方案

## 1️⃣ 容器复用（智能体 > 容器数）

### 问题场景
```
用户创建 10 个智能体，但只有 3 个 OpenClaw Pod
→ 如何让 3 个容器服务 10 个智能体？
```

### 方案设计

#### 方案 A：OpenClaw 原生多智能体支持（推荐）

**原理**：
OpenClaw 本身支持在单个实例中管理多个 Agent，通过 Agent ID 隔离。

**实现**：
```typescript
// Scheduler 维护映射表
type AgentMap = Map<AgentID, PodInfo>;

interface PodInfo {
  podName: string;
  podIP: string;
  agentCount: number;  // 当前服务的 Agent 数量
  agents: Set<AgentID>;  // 该 Pod 上的所有 Agent
  lastActivity: Date;
}

// 分配算法（最少连接优先）
function allocatePod(agentId: string): PodInfo {
  // 1. 检查该 Agent 是否已分配（保持亲和性）
  if (agentMap.has(agentId)) {
    return agentMap.get(agentId)!;
  }
  
  // 2. 选择负载最低的 Pod
  const pods = listPods(); // 获取所有 OpenClaw Pod
  const leastLoadedPod = pods.sort((a, b) => 
    a.agentCount - b.agentCount
  )[0];
  
  // 3. 检查容量限制（每 Pod 最多 10 个 Agent）
  if (leastLoadedPod.agentCount >= MAX_AGENTS_PER_POD) {
    throw new Error("容器池已满，请扩容");
  }
  
  // 4. 分配并记录
  leastLoadedPod.agentCount++;
  leastLoadedPod.agents.add(agentId);
  agentMap.set(agentId, leastLoadedPod);
  
  return leastLoadedPod;
}
```

**优点**：
- ✅ 无需修改 OpenClaw 源码
- ✅ 成本低（少量 Pod 即可服务大量 Agent）
- ✅ OpenClaw 原生支持多 Agent（通过 workspace 隔离）

**缺点**：
- ⚠️ 单 Pod 故障影响多个 Agent
- ⚠️ 需要限制每 Pod 的 Agent 数量（避免资源竞争）

**配置示例**：
```yaml
# scheduler-config.yaml
container_pool:
  max_agents_per_pod: 10  # 每个 Pod 最多服务 10 个 Agent
  min_replicas: 3         # 最少保持 3 个 Pod
  max_replicas: 20        # HPA 最多扩展到 20 个 Pod
  scale_threshold: 0.8    # 当平均负载超过 80% 时触发扩容
```

#### 方案 B：动态扩容（HPA）

**原理**：
当 Agent 数量超过容量时，自动创建新的 Pod。

**实现**：
```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: openclaw-pool-hpa
  namespace: openclaw
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: openclaw-pool
  minReplicas: 3
  maxReplicas: 20
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
    - type: Resource
      resource:
        name: memory
        target:
          type: Utilization
          averageUtilization: 80
    # 自定义指标：Agent 数量
    - type: Pods
      pods:
        metric:
          name: agent_count_per_pod
        target:
          type: AverageValue
          averageValue: "8"  # 每 Pod 平均 8 个 Agent 时触发扩容
```

**优点**：
- ✅ 自动化，无需手动干预
- ✅ 按需扩容，节省成本

**缺点**：
- ⚠️ 扩容有延迟（1-2 分钟）
- ⚠️ 需要监控指标支持

## 2️⃣ 容器回收（闲置智能体释放）

### 问题场景
```
用户创建了 100 个智能体，但只有 10 个活跃
→ 如何回收闲置容器的资源？
```

### 方案设计

#### 回收策略

```go
// Scheduler 定时任务（每 5 分钟执行一次）
func recycleIdleAgents() {
    now := time.Now()
    idleThreshold := 30 * time.Minute
    
    for agentID, podInfo := range agentMap {
        // 1. 检查最后活跃时间
        if now.Sub(podInfo.lastActivity) > idleThreshold {
            log.Printf("回收闲置 Agent: %s (闲置 %v)", agentID, now.Sub(podInfo.lastActivity))
            
            // 2. 从 Pod 中删除 Agent 工作区
            err := deleteAgentWorkspace(podInfo.podIP, agentID)
            if err != nil {
                log.Printf("删除工作区失败: %v", err)
                continue
            }
            
            // 3. 更新映射表
            podInfo.agents.Delete(agentID)
            podInfo.agentCount--
            agentMap.Delete(agentID)
            
            // 4. 持久化回收记录（用于恢复）
            saveRecycleRecord(agentID, now)
        }
    }
    
    // 5. 如果 Pod 完全空闲，考虑缩容
    for _, pod := range listPods() {
        if pod.agentCount == 0 && len(listPods()) > minReplicas {
            log.Printf("Pod %s 已空闲，触发缩容", pod.podName)
            scaleDeploy("openclaw-pool", -1)
        }
    }
}

func deleteAgentWorkspace(podIP string, agentID string) error {
    // 调用 OpenClaw Pod 的清理 API
    url := fmt.Sprintf("http://%s:18789/admin/agents/%s", podIP, agentID)
    req, _ := http.NewRequest("DELETE", url, nil)
    req.Header.Set("Authorization", "Bearer openclaw123")
    
    resp, err := http.DefaultClient.Do(req)
    if err != nil {
        return err
    }
    defer resp.Body.Close()
    
    if resp.StatusCode != 200 {
        body, _ := io.ReadAll(resp.Body)
        return fmt.Errorf("删除失败: %s", body)
    }
    
    return nil
}
```

#### 恢复策略

```go
// 当用户再次请求被回收的 Agent
func restoreAgent(agentID string) (*PodInfo, error) {
    // 1. 从数据库加载 Agent 配置
    agentConfig, err := db.GetAgentConfig(agentID)
    if err != nil {
        return nil, fmt.Errorf("Agent 不存在: %v", err)
    }
    
    // 2. 分配新的 Pod
    podInfo := allocatePod(agentID)
    
    // 3. 在 Pod 中重新创建 Agent
    err = createAgentInPod(podInfo.podIP, agentConfig)
    if err != nil {
        return nil, fmt.Errorf("创建 Agent 失败: %v", err)
    }
    
    // 4. 从 MinIO 恢复对话历史
    err = restoreChatHistory(agentID, podInfo.podIP)
    if err != nil {
        log.Printf("恢复历史失败（非致命）: %v", err)
    }
    
    // 5. 更新映射表
    podInfo.lastActivity = time.Now()
    agentMap.Set(agentID, podInfo)
    
    return podInfo, nil
}
```

## 3️⃣ Workspace 挂载（数据持久化）

### 问题场景
```
Pod 重启/删除后，Agent 工作区数据丢失
→ 如何持久化 Agent 数据？
```

### 方案对比

| 方案 | 适用场景 | 性能 | 成本 | 复杂度 |
|------|---------|------|------|--------|
| emptyDir | 临时存储，开发测试 | ⭐⭐⭐⭐⭐ | 免费 | ⭐ |
| hostPath | 单节点开发 | ⭐⭐⭐⭐ | 免费 | ⭐⭐ |
| NFS PVC | 多节点生产（小规模） | ⭐⭐⭐ | 中等 | ⭐⭐⭐ |
| Ceph PVC | 多节点生产（大规模） | ⭐⭐⭐⭐ | 高 | ⭐⭐⭐⭐ |
| S3/MinIO | 云原生，弹性 | ⭐⭐ | 中等 | ⭐⭐⭐⭐ |

### 方案 1：hostPath（当前开发环境）

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: openclaw-pool
spec:
  template:
    spec:
      volumes:
        - name: agent-workspace
          hostPath:
            path: /Users/lifeng/git/git-claw/agent-openclaw-assisant/workspace/lobsters
            type: DirectoryOrCreate
      containers:
        - name: openclaw
          volumeMounts:
            - name: agent-workspace
              mountPath: /data/agents
```

**优点**：
- ✅ 简单，无需额外服务
- ✅ Pod 重启后数据不丢失

**缺点**：
- ❌ 仅限单节点（Docker Desktop）
- ❌ 无法跨 Pod 共享数据
- ❌ Node 故障导致数据丢失

### 方案 2：NFS PVC（生产推荐）

#### 步骤 1：搭建 NFS 服务器

```bash
# 在一台服务器上（或使用云厂商 NFS 服务）
sudo apt-get install nfs-kernel-server
sudo mkdir -p /nfs/openclaw-agents
sudo chown nobody:nogroup /nfs/openclaw-agents
sudo chmod 777 /nfs/openclaw-agents

# 配置 NFS 导出
sudo vi /etc/exports
# 添加:
/nfs/openclaw-agents *(rw,sync,no_subtree_check,no_root_squash)

sudo exportfs -ra
sudo systemctl restart nfs-kernel-server
```

#### 步骤 2：安装 NFS Provisioner

```bash
helm repo add nfs-subdir-external-provisioner \
  https://kubernetes-sigs.github.io/nfs-subdir-external-provisioner/

helm install nfs-provisioner \
  nfs-subdir-external-provisioner/nfs-subdir-external-provisioner \
  --set nfs.server=192.168.1.100 \  # NFS 服务器 IP
  --set nfs.path=/nfs/openclaw-agents \
  --set storageClass.name=nfs-client \
  --namespace kube-system
```

#### 步骤 3：创建 PVC

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: openclaw-agents-pvc
  namespace: openclaw
spec:
  accessModes:
    - ReadWriteMany  # 多 Pod 同时读写
  storageClassName: nfs-client
  resources:
    requests:
      storage: 100Gi
```

#### 步骤 4：挂载到 Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: openclaw-pool
spec:
  template:
    spec:
      volumes:
        - name: agent-workspace
          persistentVolumeClaim:
            claimName: openclaw-agents-pvc
      containers:
        - name: openclaw
          volumeMounts:
            - name: agent-workspace
              mountPath: /data/agents
```

**优点**：
- ✅ 支持多节点
- ✅ 数据持久化
- ✅ Pod 可跨节点迁移

**缺点**：
- ⚠️ 需要维护 NFS 服务器
- ⚠️ 性能略低于本地存储

### 方案 3：MinIO 对象存储（云原生推荐）

**理念**：将文件系统操作转换为对象存储 API

**实现**：
```typescript
// OpenClaw 启动时从 MinIO 下载必要文件
async function initializeAgent(agentId: string) {
  const workspaceDir = `/data/agents/${agentId}`;
  
  // 1. 创建临时工作区（emptyDir）
  await fs.mkdir(workspaceDir, { recursive: true });
  
  // 2. 从 MinIO 下载配置和历史
  await minioClient.fGetObject(
    'openclaw-agents',
    `agents/${agentId}/config.json`,
    `${workspaceDir}/config.json`
  );
  
  await minioClient.fGetObject(
    'openclaw-agents',
    `agents/${agentId}/history.json`,
    `${workspaceDir}/history.json`
  );
  
  // 3. 启动 Agent
  return startAgentWithWorkspace(workspaceDir);
}

// Agent 运行时定期同步数据到 MinIO
async function syncAgentToMinIO(agentId: string) {
  const workspaceDir = `/data/agents/${agentId}`;
  
  await minioClient.fPutObject(
    'openclaw-agents',
    `agents/${agentId}/config.json`,
    `${workspaceDir}/config.json`
  );
  
  await minioClient.fPutObject(
    'openclaw-agents',
    `agents/${agentId}/history.json`,
    `${workspaceDir}/history.json`
  );
}
```

**优点**：
- ✅ 完全云原生
- ✅ 弹性伸缩
- ✅ 高可用（MinIO 集群）

**缺点**：
- ⚠️ 需要修改 OpenClaw 代码
- ⚠️ 网络延迟（特别是频繁读写）

## 4️⃣ 推荐方案总结

### 开发环境
```
容器复用: 固定 3 副本，简单轮询
容器回收: 不启用（手动清理）
Workspace: hostPath（本地目录）
```

### 生产环境（小规模 < 1000 Agent）
```
容器复用: 方案 A（多 Agent 单 Pod）+ HPA
容器回收: 30 分钟闲置自动回收
Workspace: NFS PVC (100Gi)
数据库: PostgreSQL + Redis + MinIO
```

### 生产环境（大规模 > 1000 Agent）
```
容器复用: 方案 A + HPA + 按用户分片
容器回收: 15 分钟闲置自动回收 + 冷数据归档
Workspace: MinIO 对象存储
数据库: PostgreSQL (RDS) + Redis Cluster + MinIO Cluster
```
