# 流式输出现状说明

## ✅ 已完成的优化

### 1. 前端 - Nginx 代理配置
- **位置**: `frontend-vue/Dockerfile`
- **修改**: 
  - 禁用 proxy buffering (`proxy_buffering off`)
  - 设置 SSE 必要头部 (`X-Accel-Buffering: no`)
  - 无限超时 (`proxy_read_timeout 86400s`)

### 2. Scheduler - 字节级流式转发
- **位置**: `scheduler-go/internal/api/api.go`  
- **修改**: 
  - 从 `bufio.Reader.ReadString('\n')` 改为 `resp.Body.Read(buffer)` (1字节缓冲)
  - 每检测到 `\n` 立即 `flusher.Flush()`
  - 实现真正的字节级流式转发

### 3. OpenClaw Gateway - 禁用 Nagle 算法
- **位置**: `workspace/source/openclaw/src/gateway/http-common.ts`
- **修改**:
  ```typescript
  export function setSseHeaders(res: ServerResponse) {
    // ...
    if (res.socket) {
      res.socket.setNoDelay(true); // 禁用 Nagle 算法
    }
    res.flushHeaders?.();
  }
  ```

## ⚠️ 当前瓶颈：OpenClaw Agent 运行时

### 问题现象
```
测试: curl http://localhost:30080/api/chat/stream
结果: 
  - ✅ 数据能正确返回
  - ❌ 用时 12-32 秒
  - ❌ 只有 1 个 chunk（非流式）
```

### 数据流路径分析

```
Ollama (流式✅)
  ↓ 每个 token 立即返回
OpenClaw 内部 (流式✅)
  ↓ [ollama-stream] Pushing text_delta: "HE"
  ↓ [ollama-stream] Pushing text_delta: "LL"
  ↓ [ollama-stream] Pushing text_delta: "O"
OpenClaw Gateway (聚合❌)
  ↓ 等待整个响应完成
  ↓ 一次性发送: data: {"content":"HELLO","type":"content"}
Scheduler (接收1个chunk)
  ↓ 📥 [ChatStream] 已处理 1 个 chunks
前端 (显示1个chunk)
```

### 根本原因

OpenClaw Agent 的事件触发机制有问题：

1. **Ollama Provider** (`ollama-stream.ts`) 正确实现了流式处理
   ```typescript
   for await (const chunk of parseNdjsonStream(reader)) {
     stream.push({ type: "text_delta", delta });
   }
   ```

2. **但是** `openai-http.ts` 的事件监听器没有收到实时事件
   ```typescript
   const unsubscribe = onAgentEvent((evt) => {
     if (evt.stream === "assistant") {
       writeAssistantContentChunk(res, { content }); // 没有被实时调用！
     }
   });
   ```

3. **最终** `agentCommandFromIngress` 等待完成后才输出完整响应
   ```typescript
   const result = await agentCommandFromIngress(...); // 等待整个执行完成
   if (!sawAssistantDelta) { // 没有收到流式事件，输出完整结果
     writeAssistantContentChunk(res, { content: resolveAgentResponseText(result) });
   }
   ```

### 可能的原因

1. **事件总线延迟**: `emitAgentEvent` 和 `onAgentEvent` 之间有缓冲或延迟
2. **Agent 订阅逻辑**: `subscribeEmbeddedPiSession` 可能有过滤或聚合逻辑
3. **配置问题**: Agent 或 Model 配置可能禁用了流式模式
4. **StreamFn 消费**: 流可能没有被及时消费

## 🎯 结论

当前系统已经完成了所有网络层和传输层的流式优化：
- ✅ Nginx 无缓冲
- ✅ Scheduler 字节级转发
- ✅ TCP Nagle 算法禁用

**但是** OpenClaw Agent 运行时本身在聚合响应，导致无法实现真正的流式输出。

这是 OpenClaw 内部的架构问题，需要：
1. 深入研究 `@mariozechner/pi-agent-core` 和 `@mariozechner/pi-ai` 的实现
2. 或者检查 OpenClaw 配置文件中是否有相关选项
3. 或者考虑在 Agent 层面绕过这个问题（直接调用 Ollama，不经过 Agent 运行时）
